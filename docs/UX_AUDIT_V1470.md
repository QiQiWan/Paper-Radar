# Paper-Radar v1.47.0 用户体验改版与代码审阅报告

**审阅日期：2026 年 11 月 10 日**  
**对比基线：用户上传的 `Paper-Radar_v1.46.0_Complete_GitHub_Root.zip`**  
**交付范围：本地工作台、公网工作台、使用文档、聚焦测试、静态浏览器页面审阅**  
**软件状态：研发验证版，尚非正式多平台验收发布。**

## 1. 总体结论

本版对普通用户的核心路径做了实质性修改。主线调整为 **首页 → 找论文 → 我的文献 → 研究分析 → 我的报告**，并把任务记录、学术证据追溯、研究记忆、批量管理和服务设置放在按需展开的区域。既有科研后端及数据库结构未迁移，保留 30 篇 PDF/256 项科研评测的相关研究功能与限制，不对学术分析准确率作未经检验的陈述。

本轮覆盖**原有 18 个文件的修改**，新增用户体验样式、测试与布局审阅脚本。聚焦测试 **43 项通过**；涉及公网、阅读、分析、持续跟进、双盲标注等更宽范围的回归测试 **106 项通过**。Chrome/Chromium 静态渲染检查包括本地与公网各 5 个核心页面，桌面 1440px 与手机 390px 两种宽度，共 **20 个布局场景，未检测到横向溢出**。

这些检查支持界面结构与部分代码行为正确，并不足以证明所有真实使用路径或全量科学功能已验收。

## 3. 本轮修复的具体交互与代码问题

### 3.1 检索与配置隔离

旧调用链执行检索前会执行 `save(true)`，提交包括模型服务商、API 设置、运行计划等字段在内的全部表单。新链路先校验关键词和来源，只通过 `/api/config` 提交 `keywords`、`sources`、`max_results`、`sort_mode`、`max_queries_per_source`，然后提交 `/api/job`。服务端 `/api/config` 会读取已存配置并合并已提供字段，未提交字段保留原值。这样减少了普通检索对低频配置的意外覆盖。

### 3.2 公网检索减少跨页操作

公网“找论文”新增关键词输入与公开来源勾选。执行前对 1—6 组关键词、每组长度及至少一个来源作客户端校验。只有与当前主题设置不同，才调用 `/api/public/topics/update`，并保留主题名称后提交检索。这一步会更新当前主题的长期检索条件；因此界面明确说明已保存，用户需要理解其影响。

### 3.3 研究分析的专业功能分级

日常入口使用一个研究问题与一个开始按钮；额外的研究记忆、SynthesisAgent 跨论文比较和证据修订使用折叠区域。原文定位、引用核验和实验差异的人工审核约束维持原有逻辑，没有把候选数值升级成自动确认结论。需要注意：模型生成完整科研综述时仍受已有证据和用户授权限制，不能保证自动完成一篇研究综述。

### 3.4 窄屏导航修复

初次静态页面检查发现公网移动导航曾出现标签重叠，本地隐藏部分核心导航。已按两行网格布局重构，并重新渲染首页、检索、文献、研究分析和报告页面。移动网页采用 390×844px 模拟视口；显示 0 横向溢出，不代表已覆盖所有手机、浏览器和放大字号情况。

### 可复现的检查命令

在仓库根目录执行：

```bash
python -m pip install -r requirements.txt
python -m pytest -q tests/test_v147_user_experience.py tests/test_v1401_http_ux_and_navigation.py tests/test_v1401_ui_status_and_copy.py tests/test_v1406_visual_consistency.py
```

有本机 Chromium 和 Python Playwright 时，可以使用：

```bash
python -m pip install playwright
python tools/qa_v147_layout.py
```

布局截图默认写入仓库根目录的 `qa_v147_out/`，也可用环境变量 `PAPER_RADAR_QA_OUTPUT` 指定保存位置。这项检查渲染 HTML/CSS，使用固定占位信息，不会读取或修改用户数据库。

## 5. 仍未关闭的问题与建议顺序

1. **真实用户可用性测试（P0）。** 邀请至少 5 名未接触开发的科研人员，从解压、启动、创建主题、检索、阅读、研究分析到报告导出完整操作。记录任务完成率、耗时、误操作和卡点，目标 80% 以上独立完成核心路径。当前没有实测数值。
2. **公网登录与接口浏览器联测（P0）。** 使用真实测试账号和隔离数据，验证关键词更新、选源、提交任务、进度、PDF 预览、报告浏览。现有测试涵盖服务器基本响应和前端逻辑静态断言，尚未形成真实的浏览器端到端闭环。
3. **数据不足时的报告引导（P1）。** 首页和分析页应明确“已有文献 / 已索引全文 / 人工确认结论”之间的数据质量差异；可建议补全 PDF 并给用户后续可点击操作。
4. **全量持续集成和发行验收（P1）。** 分离耗时或需要外部服务的测试，设定分组超时；之后完成 Windows/macOS/Linux 实机启动、应用更新及离线依赖检查。
5. **用户安装体验（P1）。** 目前仍为 Python 源码入口，缺少已验收的正式桌面安装包。非开发人员只需双击运行的目标需要单独交付安装程序和真实系统测试。
6. **无障碍和多尺度复验（P2）。** 补齐键盘 Tab 操作、屏幕阅读器标签、200% 放大、高对比度以及不同浏览器、手机宽度、深浅色主题的测试。

## 6. 数据与兼容性说明

- 本轮没有修改 SQL 数据库表结构和研究成果的科学评价逻辑。
- 为保留用户既有研究信息，未删除后端 API、研究证据审核和公开来源授权功能；更多操作仅折叠隐藏，不会移除。
- 升级前仍建议备份用户数据目录。不要将旧版源码的 `data/` 目录当作用户数据迁移策略。
- 研究分析的自动候选依然需要原文核对；模型调用、数据传输授权及费用限制维持原有边界。
- 本报告中的界面截图以静态示例文字渲染，不能作为已检索真实论文或已完成科学质量评估的证明。
