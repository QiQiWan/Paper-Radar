# 本地运行管理、前后台切换与安全更新

## Bash 运行方式

- `./start_macos_linux.sh`：默认前台运行，终端窗口持续显示服务输出，使用 `Ctrl+C` 停止。
- `./start_macos_linux.sh --foreground`：只为本次强制前台运行。
- `./start_macos_linux.sh --background`：只为本次后台运行，终端可以退出，后续从网页或桌面管理器停止。
- “设置 → 软件更新与运行”中的“服务运行方式”决定**下一次通过启动脚本打开时**的默认模式。运行中的进程不能直接重新挂载到已有终端。

双击原生桌面安装程序时，以图形运行管理器为入口，管理器可以随时重新接管本用户后台服务。

## 服务状态与停止

在网页“设置 → 运行诊断”查看 PID、端口和当前模式；“停止服务”会在当前任务完成时才允许关闭。管理器窗口可以执行启动、重启和停止。公网服务须使用 systemd 等正规的运维方式管理。

## 手动确认安装更新

1. 在“软件更新与运行”点击“检查版本”；若发现新的公开**正式** Release，点击“确认并安装”。自动更新需要完整可信的 GitHub 源码发布包及 SHA-256 校验，仍保留签名和备份保护。
2. 确认后停止接收新科研任务，等待当前任务结束；终端或网页会暂时断开，属于正常情况。
3. 由独立进程关闭同一用户拥有的本地服务，核实旧端口已释放，下载校验更新、备份旧代码及用户状态；通过检查后启动新版服务并恢复网页。更新期间不应手动删除 `.paper_radar_updates`。
4. 在页面检查更新结果，或查看 `.paper_radar_updates/handoff_status.json`、`.paper_radar_updates/handoff.log`。遇到超时或更新失败，系统尝试重新启动旧版；失败可按升级文档恢复备份。

保护边界：若存在生产公网服务、无法结束的后台定时任务、无权关闭的其他用户服务、被占用的程序目录，自动更新应明确拒绝或暂停。系统不会直接杀死不属于本用户的进程，不会以强制终止破坏正在写入的科研数据。

对于 PyInstaller 冻结版，应通过操作系统安装程序升级。浏览器仅提供官方 Release 的下载入口，**不会使用源码更新器直接覆盖 EXE 或 .app**。
