# Paper-Radar v1.17.0 设计审查与实施结果

版本：1.17.0｜2026-11-04｜基础版本：v1.16.0

## 1. 总体判断与实施范围

本轮集中修复公网端的长期运行短板，并提高科研比较报告的可解释性。桌面版原有 16 个 Agent、PDF 原文核验、账号门户、Ed25519 更新验证及数据库迁移继续保留。

v1.16.0 公网检索使用进程内字典保存任务状态，重启后无法追溯；同一日的检索配额写在 `auth_attempts`，但记录清理窗口只有一小时，使“每日上限”可能实际失效。同时，原跨论文报告只列出匹配条件的候选，缺少供研究人员判断证据可用性的诊断字段。

v1.17.0 新增 `paper_radar/portal_jobs.py`，采用 SQLite 持久化任务、事务化提交及双工作线程。科研比较增加证据完整性、重复记录和比较条件冲突的诊断。公网论文库新增安全分页和任务记录展示；管理员得到汇总级运行统计。

## 2. 架构与数据流

```text
Browser (HTTPS, same-origin, authenticated)
   |     register/login + session + CSRF
   v
Nginx 443  ->  Portal HTTP on 127.0.0.1:<port>
                 |             |
                 |             +-- per-account workspace database
                 |                   topics / papers / evidence
                 |
                 +-- accounts.sqlite3 / portal_auth migrations v3
                       accounts / sessions / auth_attempts
                       portal_jobs (durable)
                             |
                             +-- 2 in-process worker threads
                                     |
                                     +-- bounded arXiv metadata query
                                     +-- account-scoped idempotent inserts
```

公网端继续使用独立路由和工作区，绝不将桌面版 `webapp.py` 的本地文件、Zotero、密钥管理、更新器接口代理到公网。公网版仍为受控子集，尚未支持完整的在线全文 Agent 或在线模型凭据。

## 3. 持久化任务队列

### 3.1 状态机

- `queued`：事务提交成功；HTTP 返回 202 和 `job_id`。
- `running`：工作线程认领任务，原子增加 `attempts`。
- `success`：所有论文更新成功提交，保存任务统计。
- `failed`：工作线程捕获不可恢复异常，记录有限错误文本，避免重复请求。
- `cancelled`：排队阶段立即结束；执行中设置 `cancel_requested`，抓取或入库检查点触发安全取消。

服务重启时，未完成的 `running` 任务若此前仅尝试一次，恢复为 `queued`；达到两次尝试上限的任务标记为失败。已成功的论文使用 `INSERT OR IGNORE`，重抓时可避免重复记录。任务状态保存在磁盘，支持用户刷新页面或重新登录后查看。

**运行限制：** 此队列是**单进程 SQLite 队列**。两条 daemon 线程负责执行，默认总待运行/正在运行任务上限 100，每账号同时只允许一个进行中的任务，每账号滚动 24 小时最多提交 10 次。任务历史保留 90 天，超期历史在新任务成功提交时清理。它目前不支持多进程水平扩容、外部任务 broker、强制杀死阻塞调用或取消后的自动费用退还。

### 3.2 事务与并发安全

同一事务完成：检查账号已有任务、全局待办上限、24 小时次数、插入任务。重复请求或队列已满时，事务回滚，不扣检索配额。通过 SQLite `BEGIN IMMEDIATE` 串行化竞争提交，防止并发多次扣费/产生重复活动任务。数据库额外设置同账号活动任务部分唯一索引作为最后的保护。

任务认领、状态变更和结果保存也在短事务中执行；网络请求在数据库事务外进行。取消信号触发在论文库事务中回滚，未提交的新增论文不会部分写入。账号停用时自动请求取消其排队或正在执行的任务。

### 3.3 HTTP 与 UI 合同

| 方法 / 路径 | 作用 | 权限 |
| --- | --- | --- |
| `POST /api/public/search` | 返回 202，`{state:'queued',job_id}` | 当前用户 + Origin + CSRF |
| `GET /api/public/jobs` | 查询当前用户最近任务 | 当前用户 |
| `GET /api/public/jobs/history?limit=10` | 最近 1—30 次任务，不含其他账号 | 当前用户 |
| `POST /api/public/jobs/cancel` | 取消当前账号指定任务或最新活动任务 | 当前用户 + Origin + CSRF |
| `GET /api/public/admin/jobs` | 查看队列状态总量与24小时成功/失败统计 | 管理员 |
| `GET /api/public/papers?topic_id=...&limit=30&offset=0` | 当前主题论文分页，返回 `total` | 当前用户 |

页面重新打开后自动查询服务器最新任务并恢复轮询；排队显示位置、运行显示尝试次数；终态停止轮询并读取历史。论文单页默认 30 篇，最多允许一次查询 100 篇，最大偏移 5000，避免无界数据库查询和页面渲染。

## 4. 账号安全与反向代理

保留每账号独立工作区、密码 scrypt 哈希、Session/CSRF、Host 和 Origin 校验。修复 `throttle` 历史清理过早的问题：保留最近七天尝试记录，确保过去 24 小时的检索配额可以生效。

为多用户 Nginx 部署新增可选的受信反向代理客户端 IP 模式：设置 `PAPERRADAR_TRUST_PROXY_IP=1`，后端仅在请求来自 `127.0.0.1` / `::1` 时读取经过 IP 地址格式校验的 `X-Real-IP`；默认不信任这个头。**Nginx 必须覆盖该头，且公网端口仍只绑定本机回环地址**。不可直接信任客户端提供的 `X-Forwarded-For`。如前置多个代理，需明确配置其信任链，否则应保留默认设置。

公网服务仍欠缺邮箱验证、找回密码、验证码/机器人防护、审计留存策略及大规模用户访问的代理层流量治理。部署在公网前应根据使用规模补齐，特别不宜默认面向陌生公众无限制开放注册。

## 5. SynthesisAgent 科研比较质量改进

基于 v1.16.0 `compare_records()` 的字段匹配候选，新增：

1. 对同篇、同数值和同原文的记录去重，统计重复条数。
2. 显示没有 PDF 指纹来源校验的记录数量，不把用户 CSV 导入认定为已复核学术证据。
3. 提示数据集/方法类型/指标/实验条件不完整，以及缺少对照基线的记录数量。
4. 提示同一论文、相同条件下出现多条不同数值，供研究人员核查是否存在不同运行或实验口径。
5. 对相同数据集和指标但不同实验条件的记录进行分组计数，禁止直接并排排名。
6. 对比较候选补充基线不一致、来源尚未核验、百分号单位不一致等复核提示。
7. Markdown 报告增加“数据完整性与可比性诊断”，在线门户显示关键统计。

**学术边界：** 字段一致仍不足以证明实验可比。系统没有解析出相同训练/测试划分、不同单位、统计显著性、训练预算与硬件条件时，必须保留“待人工核查”标记。当前不自动计算跨论文领先幅度，不以简单年份统计解释行业趋势。

## 6. 数据库迁移及兼容

`portal_auth` schema 从 v2 增加 v3 `persistent_search_queue`，新增表、状态索引及账号活动任务部分唯一索引。迁移执行于 SQLite 事务中，保存校验摘要；遇到比本程序更新的 schema 或校验不一致即拒绝启动。`research` 与 `portal_workspace` schema 本轮不改变；旧账号、会话、主题、论文、导入的实验 CSV 继续保留。

**升级前备份：** 至少备份 `accounts.sqlite3`、`users/` 目录、桌面 `settings.json`、`data/`、`downloads/` 和 `reports/`。升级已部署的公网实例需先停止服务，确认无后台检索，再更新程序并启动；公网实例不执行运行中热更新。

## 7. 验收范围与下一阶段

自动化测试覆盖旧功能回归与新增的：并发任务提交、额度原子性、重启恢复、取消、跨账号历史隔离、管理员权限、数据库迁移、分页、比较结果诊断，以及 HTML/JavaScript 控件合同。

仍需在目标环境验收真实 arXiv 网络故障、大文件/大量账号、真正的 Nginx HTTPS 流量、Windows 自动更新与跨版本数据库迁移备份恢复。此轮没有实现真实邮件验证、分布式任务队列、独立 worker 进程或模型自动生成的领域结论。

下一阶段排序：①反机器人、邮箱验证、运维监控；②进程隔离/可终止的长任务与可恢复下载；③全文表格数据模型与跨论文指标元数据标准化；④引入真实人工标注集，测量推荐 Precision@10、证据准确率与用户阅读收益。

### 上游 arXiv 公共 API 节流

公网并发 worker 在调用**真实** `fetch_arxiv` 前，额外通过进程内互斥锁及账号数据库中的 `source:arxiv_public` 访问记录实现全服务串行和至少四秒的请求间隔。该节流键随数据库持久化，服务重启后不会立刻清零。任务等待源访问窗口时可接受取消请求。外部数据源自身仍可能返回 429/503 或发生网络重试，服务器必须保留失败记录和遵守 arXiv 的最新公开接口政策。
