# v1.49.3 研究任务运行诊断

## 目的

让使用者通过一个运行编号判断某次研究分析到底完成了哪些阶段、模型有没有调用、为什么没有形成科研结论，以及下一步应当排查什么；同时避免原始科研问题、论文内容和 API 密钥进入默认日志。

## 导出文件及含义

| 文件 | 包含内容 | 适合排查 |
|---|---|---|
| `README_FIRST.md` | 中文速览、最近任务状态和计数 | 第一次阅读诊断包 |
| `research_runs.json` | 近几次分析的运行编号、五阶段、模型状态、候选/证据数量 | 分析是否真正执行及停在哪一步 |
| `summary.json` | 最近最多 500 个结构化事件的请求失败、慢请求和错误类别 | 高频故障 |
| `runtime.jsonl` | 逐行结构化运行事件、异常类名、代码位置和耗时 | 按运行编号或错误编号定位 |
| `manifest.json` | 文件清单及是否包含可选任务日志 | 分享前检查 |

五个阶段标识为 `inquiry_collect`、`inquiry_match`、`inquiry_audit`、`inquiry_model_rank`、`inquiry_compose`，每条只记录运行状态、耗时和安全的数量指标。`inquiry_saved` 表示数据库保存完成。模型阶段的结果需要单独看：

- `MODEL_DISABLED`：本次未启用模型，可能是用户取消选项，也可能是没有可用密钥后由前端降级。
- `MODEL_SKIPPED`：模型任务没有满足执行条件。
- `MODEL_USED`：模型输出通过了协议校验，仍需核查是否产生具体建议；不能据此判定论文实验结论正确。
- `MODEL_RESPONSE_INVALID`：模型输出格式错误、虚构题录编号或输出不符合约束。
- `MODEL_TIMEOUT` / `MODEL_TRANSPORT`：模型超时或连接错误。
- `CANDIDATE_ONLY`：本次只获得元数据候选，没有人工确认的 PDF 结论。
- `CITED_EVIDENCE`：结果中存在当前有效、人工确认且具有原文锚点的结论。

## 注意

`runtime.jsonl` 的异常记录默认不包含异常信息全文或请求正文；只有异常类名与有限的代码位置。分析过后仍需查看外网环境与用户机器上的真实 PDF 状态。默认日志最多保留三轮文件，并且 `summary.json` 只有有限采样窗口，不代表完整历史统计。手动勾选“附加任务日志”后，应当人工检查自由文本中是否包含研究主题或本地路径。

## 版本验收

测试覆盖 5 个阶段、模型输出非法的降级、用户内容不进入导出包、浏览器显示最近研究任务，以及从诊断包核查阶段/结果的链路。真实付费模型的多轮请求、长时间稳定运行和真实 60 篇论文 PDF 的分析质量仍未完成实机验证。
