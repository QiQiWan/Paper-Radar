# v1.49.2 运行日志查看与问题定位

系统日志按三个层次查看：页面“运行概况”用于识别最近的错误类型；`runtime.jsonl` 用于根据错误编号定位请求和代码位置；手动任务日志与检索来源诊断用于分析具体数据处理过程。

登录本地工作台，进入 **设置 → 运行记录 → 刷新**，可看到最近的 HTTP 失败、模型调用异常、断线次数和超过五秒的请求。点击 **下载运行日志**，ZIP 包中有 `summary.json`、`runtime.jsonl`、`manifest.json` 和阅读说明。`summary.json` 只统计日志尾部最多 500 条结构化事件，不能推算全过程的失败率。

## 常见错误类别

| 错误码或事件 | 含义 | 检查办法 |
|---|---|---|
| `MODEL_CONSENT_REQUIRED` | 尚未允许将研究问题发送给模型 | 进入模型连接设置确认权限 |
| `MODEL_KEY_MISSING` | 当前模型服务商未配置 API Key | 在模型设置页面配置密钥 |
| `MODEL_CONNECT_FAILED` | 模型接口暂时无法连接 | 检查地址、DNS、代理、网络和服务商状态 |
| `AI_PLAN_FORMAT_INVALID` | 模型输出没有提供足够的有效检索词 | 查看模型配置和重新描述研究目标；可手动填写英文关键词 |
| `CLIENT_DISCONNECTED` | 浏览器中断、请求取消或网络连接关闭 | 如任务状态未完成，先看任务历史；本事件不代表数据库损坏 |
| `DATABASE_UNAVAILABLE` | 实际数据库读写失败 | 检查目录权限、磁盘空间、SQLite 与进程并发 |
| `INTERNAL_ERROR` | 程序出现未预料的内部异常 | 按错误编号对照诊断记录中的 Python 调用位置 |

**不应通过反复重启来修复已提交的模型或检索任务。** 请先打开任务中心检查是否已完成，避免重复计费和重复抓取。客户端断线后下载日志不需要停止服务。

诊断包默认不包含研究目标正文、模型密钥、Cookie 和 PDF。若主动勾选“附带任务日志”，日志可能包含研究主题，需要在分享前检查。不能通过日志恢复旧版本尚未记录的模型原始响应。
