# Paper-Radar v1.13.0：Agent 重构审查

## 结论

现有 v1.12.0 的能力可以可靠地模块化。原问题集中在 `core.run_cycle()` 内的检索、AI、存储及报告的串行耦合，难以定义各功能边界和失败责任。本轮把执行职责实际拆为九个 Agent，保留旧 API 并新增契约与阶段轨迹。

## 本次实现与证据

| 项目 | 变更 | 验证 |
|---|---|---|
| Agent 拆分 | 9 个 `stages/*.py` 文件 + 统一注册表 | 依赖图、注册、独立单元测试 |
| 兼容性 | 旧 `core.run_cycle()` 调用新 Agent 工作流 | 原有 155 项回归通过 |
| 故障隔离 | 关键步骤失败终止、非关键步骤失败继续 | Mock 故障注入及部分完成传播 |
| 可观察性 | 每阶段状态、运行耗时、版本和整数指标 | SQLite 运行轨迹及隐私检查 |
| 前端 | 设置页查看 Agent、最近状态、刷新 | 桌面/手机离线浏览器检查 |
| 文档 | 架构、研发清单、API、升级、更新日志 | 链接与版本一致性检查 |

## 后续优化空间

优先补齐模型路由与费用预算、来源质量与召回率评估、全文结构化证据分析、跨论文比较和知识问答。建议先依据 `docs/agents/README.md` 并行开展小规模工作流评测；新功能必须通过统一数据契约和回归测试后才能接入正式运行。

本轮的 Agent 实现为固定任务 DAG，没有引入自动工具委派、分布式执行、断点中途恢复或复杂 RAG；上述能力需要单独实施和验收。具体方案见 `docs/AGENT_ARCHITECTURE_V1.13.0.md`。
