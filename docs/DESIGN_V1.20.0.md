# Paper-Radar v1.20.0：五入口工作台、论文阅读状态与交互效果审查

版本：1.20.0 | 日期：2026-11-05 | 基线：v1.19.1 | 范围：公网门户、桌面导航、主题论文数据库、相关接口及测试。

## 1. 研发判断与完成范围

**本轮已经完成 v1.20.0 的可运行界面与必要的后端状态闭环。** 公网版将原先全部功能纵向堆叠的长页面重新分配为五个业务视图：工作台、论文库、任务中心、研究报告、我的账号。桌面版增加独立任务中心，并将 Zotero 和 PDF 下载整理为扩展工具入口。保留既有 16 个 Agent、独立 Worker、任务租约、报告快照、云端模型授权和升级机制。

用户打开首页即可查看当前研究主题论文数、星标数、已读数、报告数、最近任务及最近论文。任务中心承担任务提交、阶段轨迹、取消及失败排查；论文库承担搜索、筛选、阅读反馈和全文证据；报告中心承担历史快照及只读阅读；我的账号提供密码与管理员控制。五个入口采用同一页面内的明确视图切换，并将视图和主题写入 URL hash，因此支持浏览器前进、后退及刷新恢复。

**已实现的范围必须与后续计划区分：** 公网端仍通过受控 arXiv 检索和账号工作区提供科研功能，桌面端拥有 Zotero 与本地文件能力；本轮尚未实现 PDF 双栏全文阅读、实验条件矩阵、统一账号同步或完整的前端组件工程化。

## 2. 页面信息架构

| 业务入口 | 主要问题 | 展示与操作 | 对应服务 |
| --- | --- | --- | --- |
| 工作台 | 当前研究有什么进展？ | 当前主题、四项摘要指标、最新任务、最近收录、快捷启动 | `/api/public/dashboard`、任务摘要、主题列表 |
| 论文库 | 哪些论文值得进一步研究？ | 关键词检索、相关性及阅读状态过滤、排序、星标/反馈、全文证据 | `/api/public/papers`、`/api/public/papers/flags`、PDF/全文接口 |
| 任务中心 | 哪一步正在进行，结果是什么？ | 公开检索、完整研究、模型授权、阶段历史、失败和取消 | 既有 jobs/详情/取消、research/start 接口 |
| 研究报告 | 研究成果在哪里？ | 历史报告、只读在线阅读、Markdown 下载、证据 CSV 导入 | 既有 reports/list/view、research/synthesize 接口 |
| 我的账号 | 数据及账号是否安全？ | 修改密码、账号隔离说明、管理员账号与任务概况 | 既有用户认证及管理接口 |

移动端采用底部固定五入口导航，页面主体单列；桌面端采用左侧持续导航。全局研究主题在顶部统一切换，切换后同步刷新论文、统计与报告。任务和报告页面继续遵守账号访问控制。

### 2.1 主要任务路径

1. 首次注册/登录后，选择默认研究主题，或在工作台展开“管理研究主题”添加名称与 1—6 组检索词。
2. 通过“开始文献追踪”进入任务中心，选择“仅检索 arXiv”或“一键完成科研分析”。云端分析需要主动勾选授权。
3. Worker 领取任务后，用户可在任务中心查看真实阶段事件；刷新页面不影响后台运行。
4. 返回论文库，根据关键词、星标、未读/在读/已读、推荐反馈筛选论文；阅读状态自动写入当前账号及当前研究主题。
5. 在研究报告中找到历史快照，在线只读阅读；需要分享或归档时下载 Markdown。

页面不会根据阶段数推算伪造的百分比进度，也不会把用户导入的未核验证据与已完成 PDF 校验的记录混为一谈。

## 3. 数据库与接口设计

**本轮采用向后兼容的附加表，防止破坏已有论文关联结构。** `portal_workspace` 从 v3 迁移至 v4，新增 `topic_paper_flags`，以 `(topic_id,paper_id)` 为主键，保存 `is_starred`、`reading_status ∈ {unread,reading,done}`、`feedback ∈ {-1,0,1}`、`updated_at`。旧版 `topic_papers` 二列结构保持不变。没有产生过操作的论文按未读、未星标和中性反馈展示，旧的报告快照/证据不迁移重写。

| 接口 | 方法 | 请求约束 | 响应 |
| --- | --- | --- | --- |
| `/api/public/dashboard` | GET | `topic_id`，服务端验证当前用户对主题的访问 | 当前主题 `papers,starred,read,reports,recent` |
| `/api/public/papers` | GET | `q` ≤120 字、`filter` 枚举、`sort` 枚举、`limit` 1–100、`offset` ≤5000 | `papers,total,limit,offset`；记录包含当前主题星标、阅读状态与相关反馈 |
| `/api/public/papers/flags` | POST | `topic_id,paper_id`，至少一个 `is_starred / reading_status / feedback` | 更新后的标志与阅读状态 |

后端首先验证登录账户和研究主题，再检查论文确实属于该主题。数据库查询使用参数化 SQL，排序字段只允许固定白名单，搜索词内 `%`、`_`、`\\` 按字面量转义。写操作维持 CSRF 和 Origin 校验；无效枚举/字段返回 400，无权访问或不存在的论文返回 404。跨主题与跨账号标志互不影响。

这套权限仍运行在此前的受控多账号单主机部署架构下。生产环境需要 HTTPS/Nginx、备份与独立 Worker，网页不会暴露桌面版私有 API、系统文件管理或模型密钥配置接口。

## 4. 前端实现及视觉规则

- 公网静态文件：`paper_radar/static/portal.html`（五业务视图）、`portal.css`（统一设计 Token、导航和响应式布局）、`portal.js`（路由、主题与筛选状态及数据请求）。继续使用原生 JavaScript，避免本轮为界面重构引入额外前端依赖。
- 桌面静态文件：`index.html`、`app.css`、`app.js`。增加任务中心一级导航；Zotero 与 PDF 下载保留为“扩展工具”，避免历史功能丢失。
- 全局布局：桌面主栏宽度自适应，手机单列和固定底部导航；移动端报告表格在表格容器内滚动，防止整页横向溢出。
- 字体与颜色：以清晰的主次层级组织信息；辅助文字沿用 v1.19.1 修复后的高对比度配色；输入框、按钮、链接保留可见的键盘焦点状态。
- 用户反馈：任务状态读取持久化事件；报告加载使用只读快照。网络失败保留既有错误提示，不静默伪造成功状态。
- 搜索：当前主题内服务端检索及排序，客户端限制频繁输入请求；每次先加载 12 篇，再按需加载更多。

### 4.1 页面效果审查结果

使用真实 HTML/CSS/JavaScript 与模拟 HTTP API 在 Chromium 运行，检查宽度 320、375、390、768、1024、1440px：工作台及论文库均未发生水平溢出或页面 JS 异常。主要交互测试涵盖注册、导航、论文检索、星标状态、过滤、报告查看及浏览器路由。

在 390px 宽度、固定模拟数据下，**新工作台全页高度约 1571px**。此前 v1.19.1 审阅中手机工作台高度约 3372px，但两版模拟内容不完全相同，因此这一差异是信息密度和结构收束的参考，不能直接视为严格的同比任务效率指标。真实服务器浏览器访问、终端用户任务完成率与读屏器支持仍未实测。

### 4.2 审阅结论

相较 v1.19.1，新版本明显提高了研究入口、任务、报告及阅读管理的独立性。工作台不再附带所有高级设置，手机端无需为打开报告穿过完整论文列表。仍待优化：跨页保持更细粒度的筛选条件、通知/错误码标准化、深度 PDF 对照阅读、报告比较矩阵、桌面与公网 UI 细节统一、独立前端模块拆分。

## 5. 可靠性、安全和发布边界

- 数据：原有账号数据库 `portal_auth` v6 不变；用户工作区 `portal_workspace` v3→v4。升级前停止 Web 与全部 Worker，备份 `accounts.sqlite3`、`users/`，否则数据库新版本可能不被旧代码识别。
- 执行：Web/Worker 分离、租约令牌、报告快照保存、PDF 隔离、账号停用、云模型授权和签名更新均按原有机制保留。
- 安全：新增接口继续采用账号+课题双重校验、服务端白名单、参数化查询和 CSRF。浏览器渲染原文与模型文本继续通过安全 DOM API，避免执行不可信 HTML。
- 发布完整性：源码 ZIP 保留 `benchmarks/real_papers_v1/` 评估种子、Web/Worker 双入口；修复其发布文件白名单与自动安装白名单的不一致，避免独立解压缺失关键资源。
- 自动更新：该交付包没有用发布者生产 Ed25519 私钥签署，只有仓库维护者上传符合签名协议的 Release 三件套之后，受信任旧客户端才能自动安装。不能把开发 ZIP 标记成已经签署的正式更新。

## 6. v1.21+ 研发建议与验收指标

| 优先级 | 下一项研发 | 验收标准 |
| --- | --- | --- |
| P0 | 任务异常恢复操作与标准错误码 | 失败任务给出具体诊断、受支持的重新提交入口；所有重试不得绕过收费模型确认 |
| P0 | 真正面向用户的浏览器端 E2E | 在真实 HTTPS 或本地可达服务环境自动化运行登录、主题、检索、报告、账号隔离流程 |
| P1 | PDF/证据双栏阅读 | 点击实验指标即可定位 PDF 页码；版本指纹失效立即提示 |
| P1 | Synthesis 比较矩阵 | 分离可比候选、不可比和缺失信息；全部结论可溯源 |
| P1 | UI 模块化与无障碍专项 | JS 业务模块拆分、读屏器与键盘全流程验收，普通文本对比度至少 4.5:1 |
| P2 | 真实科研人员体验测量 | 至少 5 名不同熟练度用户，记录任务完成率、操作时长、误操作及反馈 |

**总体判断：** v1.20.0 为可运行的信息架构改版，科研底层模块得到保留；研究阅读深入体验与真实生产负载属于后续专项研发。
