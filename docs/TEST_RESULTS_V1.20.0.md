# Paper-Radar v1.20.0：自动化测试与界面效果审阅

日期：2026-11-05 | 基线：v1.19.1（327 项通过） | 工具：Python 3.13、pytest、Node.js、Chromium。

## 一、审阅结论

核心研发目标已按可执行代码完成：公网五入口导航、手机底部导航、首页摘要、论文搜索/筛选/排序、星标/阅读状态/相关性反馈，及桌面端任务中心。关键数据由服务器保存，登录权限与数据库隔离经过真实 HTTP 请求测试。

本轮提供两类互补证据：①真实 Python HTTP 服务器接口及 SQLite 迁移回归；②使用真实 HTML/CSS/JS 与模拟 HTTP 结果的浏览器交互/响应式检查。浏览器模拟测试**不等同于真实公网 HTTPS/Nginx 的端到端验收**。

## 二、自动化回归

执行：`python -m pytest -q`（从项目根目录运行）。

- 原 v1.19.1 基线：327 项测试通过。
- v1.20.0 端到端 API 及 UI 约束新增测试：本轮增加包括旧工作区迁移保留、Worker 打包完整性在内的专项测试。
- **完整回归：338/338 项通过（含新增 11 项专项测试）。** 本版还单独检查 `python -m compileall -q paper_radar tests tools`、`node --check paper_radar/static/portal.js`、`node --check paper_radar/static/app.js`、`python -m paper_radar.agents doctor`。
- 旧源数据测试：先以 v3 的 `portal_workspace` 结构保存论文、主题关联及报告快照，再迁移 v4。原数据仍可读取，新 `topic_paper_flags` 可以新增记录。
- 安全测试：登录后的不同用户无法操作对方论文；同一账号不同主题标志隔离；非法筛选、非法更新字段、缺失 CSRF、非同源 Origin 受到拒绝。
- 查询测试：排序仅固定白名单；LIKE 查询将 `%`、`_` 转为字面量，避免因通配符出现意外大量匹配；长度限制和分页边界有测试。
- 发布完整性：断言源码归档保留桌面与公网、Windows 与 Linux 四组启动脚本，特别是独立 Worker 启动脚本。

## 三、浏览器页面检查

测试方式：在 Chromium 中加载真实 `portal.html`、`portal.css`、`portal.js`，并以测试桥接模拟用户注册、已收录论文、任务、报告及 API 响应。测试数据仅用于验证布局及交互。分别验证注册、菜单路由、主题切换、浏览器返回、星标筛选、关键词搜索、历史报告只读预览、桌面任务中心布局。

| 视口宽度 | 公网工作台水平溢出 | 公网论文库水平溢出 | 备注 |
| ---: | ---: | ---: | --- |
| 320px | 0px | 0px | 窄手机，底部五入口导航 |
| 375px | 0px | 0px | 常见手机 |
| 390px | 0px | 0px | 单列卡片、底部固定导航 |
| 768px | 0px | 0px | 平板断点 |
| 1024px | 0px | 0px | 中等屏幕 |
| 1440px | 0px | 0px | 桌面左侧导航、工作台统计 |

390px 下新工作台在固定模拟数据中约 1571px 高；此前 v1.19.1 审阅的整页约 3372px，**两组数据内容不同，不能作为严格的同条件提升比例**。页面无未处理 JS 异常。桌面本地界面分别在 390、768 和 1440px 宽度下静态截图核查，无整页横向溢出。`qa/browser_findings.json` 保留逐视口记录。

## 四、实际审阅的剩余问题

1. 公网路由在单 HTML 文件内按业务视图切换，尚未拆成独立的编译型页面/组件包；后续继续扩大功能需要分拆前端业务模块。
2. 桌面/公网保留不同技术栈和部分视觉细节，目前只有主要业务导航趋于一致，尚未完成共享组件库。
3. 论文库主要为列表与阅读管理，复杂 PDF 表格、原文双栏对照和证据高亮仍属于下一版功能。
4. 任务状态反映后端已保存的事件，不能把未执行的阶段推算成真实的百分比进度；费用估算仍需实际模型计费数据核对。
5. 正式公网域名、Nginx HTTPS、真实浏览器直连后端、Windows 自动更新、读屏器和真实科研用户任务完成率未在本环境实测。

## 五、上线验收建议

先在目标服务器启动 Web 与 Worker，再用两组测试账号各自建立主题并并发提交受限的小任务；验证论文数据互不可见、星标不会跨账号/课题传播、报告可以只读打开。停止/重启 Worker，验证租约不重复消费；模拟无模型密钥和下载失败，确认任务可诊断且不会伪造分析结果。最后进行真实浏览器移动端 320—1440px 的账号、键盘导航和辅助技术专项检查，并制定实际用户研究任务的计时指标。

## 六、发布包约束

正式源码归档使用 `tools/package_release.py` 按 `Paper-Radar_v1.20.0_Source.zip` 命名并验证升级 ZIP 白名单。评估基准 `benchmarks/real_papers_v1/` 和根目录 Web 启动器、 `start_public_worker_macos_linux.sh`、`start_public_worker_windows.bat`。本轮修复了独立 Worker 启动器及真实论文 benchmark 不在发布/安装白名单内导致的独立解压运行失败，新增回归测试固定此行为。发布包不包含用户数据和生产私钥。
