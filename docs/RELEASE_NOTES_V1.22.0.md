# Paper-Radar v1.22.0 — 全文实验页召回与科研证据质量收敛

发布日期：2026-11-05。基于 v1.21.2 完整源码连续升级；桌面检索、公开门户路由、用户工作区、签名更新机制保持兼容。

## 本版功能

1. **全文实验页筛选。** 公网 PDF 解析不再只把前八页正文交给云端。`portal_evidence_retrieval.py` 对已解析的每页文本按表格、实验、结果、评价指标等词汇打分，兼顾 PDF 的前、中、后三个区域，选取最多 12 页，每页最多 3400 字符。候选页保留物理 PDF 页码；只对已入库的、SHA-256 一致的 PDF 生效。长页面通过原文连续窗口选择局部正文，不拼接不相邻段落。
2. **受限分批实验抽取。** 单篇最多 3 批、每批最多 4 页，模型输入与输出有界；每个账号滚动 24 小时最多 8 次实际云模型调用。用户必须主动勾选云端分析，管理员也需要分别配置模型地址、模型名和访问密钥。服务器使用固定 35 秒调用时限和结构化 JSON 验证，无法核验的数值不入库。
3. **失败收敛与缓存。** 每批独立校验。部分请求超时或模型输出错误时，保留已经确认的引文、页码和数值，任务结果明确标记为“部分完成”；不会把部分结果写成已完成分析缓存。重新执行分析时会重新评估候选页并发起必要的调用，**目前尚未实现逐批断点续跑**。完整批次均成功时，分析结果才可缓存并避免重复调用。PDF 文件指纹变化会废弃旧索引与证据。
4. **证据来源与学术比较。** 公网上传 PDF 的已验证引文不再被误记为“未校验”；其书目身份仍需人工复核。跨论文数据集/指标/实验条件匹配只产生人工复核候选，增加基线差异和百分号表达冲突统计，以及明确的复核清单。不会自动计算跨论文性能提升或排序。
5. **任务和成本透明。** 网页任务详情展示已解析页数、候选页码、已尝试/成功/失败的模型批次和被证据校验拒绝的结果条数；云端模型次数与检索、单篇分析、报告生成次数分别展示。
6. **真实论文评估接口。** `tools/eval_real_papers.py score` 增加 `candidate_page_recall`（人工标注的物理页被候选页筛选命中的比例）与 `candidate_excerpt_anchor_recall`（实际发送片段中同时保留数值和方法锚点的比例）。只有本地具有真实 PDF 时才计算；未提供真实 PDF 返回 `null`，绝不将人工预录标签冒充为模型自动抽取结果。

## 部署参数与代价

- `PAPERRADAR_PUBLIC_LLM_KEY`、`PAPERRADAR_PUBLIC_LLM_MODEL`、`PAPERRADAR_PUBLIC_LLM_BASE`：开启服务器模型接口所需；未配置会返回部分完成及说明。
- `PAPERRADAR_JOB_TIMEOUT`：独立 Worker 单任务默认 480 秒（之前 150 秒）。
- `PAPERRADAR_CPU_SECONDS`：独立 Worker 子进程 CPU 上限默认 240 秒；空闲和非模型任务也沿用此预算，但实际 CPU/时间用量不受保证。
- 单篇 PDF 最大 12 MiB；PDF 文本解析最多处理 40 个物理页、每页前 4800 字符、单篇抽取 110000 字符；**扫描版 PDF 尚未提供 OCR**。长文档的后部附录、跨页表格仍可能漏检。
- 模型调用每篇最高三次；完整科研任务最多尝试下载和分析两篇 PDF。账单按实际提供商报价、输入输出 token 和缓存政策计费，软件不会推断费用。

## 无损升级与恢复

1. 停止公网 Web 和所有独立 Worker，备份整个 `PAPERRADAR_PORTAL_DATA` 文件夹及旧程序代码；检查备份完整性，记录当前服务版本与回滚方法。
2. 使用 v1.22.0 源码包替换程序代码，保留 `.env`、个人工作区、`storage/`、`data/`、`settings.json` 等运行数据，切勿将源码包直接覆盖到数据目录。新版本不添加数据库迁移，首次启动会沿用现有迁移校验。
3. Windows 启动 `start_public_worker_windows.bat`；Linux/macOS 启动 `start_public_worker_macos_linux.sh`。使用 Nginx 的部署须继续应用 v1.21.1 的 PDF 专用 `client_max_body_size 13m` 配置、执行 `nginx -t` 后再重载。
4. 验证 HTTP 登录/鉴权、创建主题、arXiv 网络超时、PDF 上传、全文索引、候选页分布、模型配置失败、人工证据复核、报告快照以及取消任务。核实云模型未授权时不存在外发调用。
5. 发生不可恢复错误时停止 Web 与 Worker，恢复原代码及全量备份数据库，再重新启动，**不要让两个版本同时操作同一用户工作区**。

本地源码 ZIP **没有发布私钥生成的正式 Release 签名**。要进入受信自动更新渠道，需由仓库发布者使用生产私钥生成签名清单，并经 Windows 实机和正式公网环境验收；不能仅凭 ZIP SHA-256 文件宣布已完成正式签名或安全发布。

## 复现与验收

```bash
python -m pytest -q
python -m paper_radar.agents doctor
python tools/eval_real_papers.py score
# 真实 PDF 下载须在可访问 arXiv 的环境中由操作者主动执行：
python tools/eval_real_papers.py fetch
python tools/eval_real_papers.py score
# 若有人工独立标注的模型输出，可额外执行：
python tools/eval_real_papers.py score --predictions model_predictions.json
```

新增 `tests/test_v122_fulltext_and_synthesis.py` 使用程序生成的 20 页合成 PDF 和受控模拟模型，覆盖后部实验页、跨批次失败、缓存、配额、证据可追溯以及合成的可比/不可比判定。**这些合成测试不能代替真实论文的端到端学术准确率**。真实 3 篇论文、6 条人工校核条目、5 个不可比关系的种子集仍需要扩大，并增加足量可比正例。

完整的真实 PDF 多用户生产压测、Windows 本机自动更新、浏览器级视觉回归、Nginx HTTPS、真实云模型费用与学术准确率仍待在用户实际环境执行，不能把离线测试结果当作已完成生产验收。
