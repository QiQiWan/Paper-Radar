# Paper-Radar v1.18.0：公网多账号科研任务工作流与安全稳定性审查

版本：v1.18.0；基线：v1.17.0。本文区分已提交代码、自动化测试和待生产验收。

## 一、核心结论

公网版实现了同一账号内“发现文献 → 获取或上传开放 PDF → 受限解析全文 → 可选大模型实验数据提取 → 原文片段核验 → SynthesisAgent 比较与报告”的任务闭环。各账号文献、PDF、PDF 片段和核验结果均位于该账号独立工作区。桌面端 Zotero、系统密钥和自动更新管理接口仍不暴露到公网。完整链路已使用模拟检索源和合成 PDF 通过端到端测试；公开互联网环境与真实云模型尚未通过验收。

## 二、实际模块与边界

| 模块 | 输入 | 实际输出 | 风险与缓解措施 |
| --- | --- | --- | --- |
| PortalAuth | 用户名、密码、Cookie | 有效会话与账号标识 | scrypt 密码哈希、会话服务端撤销、CSRF 与 Origin 核验、限流 |
| PortalJobs | 账号、主题、任务类型、选项 | 持久化任务、执行状态 | 同账号仅一活动任务、全局队列上限、至多一次重启重试、单实例排他锁 |
| Discovery | 主题关键词、公开来源 | 题录和主题论文关联 | arXiv 全局串行访问、持久限流、单次最多20篇 |
| PDF Acquire | arXiv ID 或认证用户 PDF | 专属账号 PDF | 拒绝任意 URL 和文件路径、重定向主机白名单、每篇12MiB、按账号总量限制 |
| Fulltext | 已存储 PDF 指纹 | 逐页原文 | 独立子进程、28秒超时、40页/文本上限、Linux CPU/内存限制 |
| Experiment | 用户明确授权、服务器配置模型 | 提议的结构化实验记录 | 默认不开启云调用、仅发有限文字片段、用户/服务端额度、严格 JSON 字段 |
| EvidenceVerifier | AI 输出、原文片段 | 有页码、逐字引文的结果 | 引文及指标数值须能在同一片段核实，PDF 指纹变化拒绝旧结论 |
| SynthesisAgent | 本账号当前主题证据 | Markdown 与比较候选 | 标记用户导入的未核验证据，不直接做跨论文性能提升排名 |
| Portal Admin | 管理员会话 | 账号启停与聚合统计 | 不暴露其他用户完整论文数据；停用用户后会话撤销与任务取消 |

## 三、核心工作流

1. 研究主题的每次自动化执行使用 `research` 类型的持久化任务；旧版 `search` 继续可用。
2. 按主题检索最多20条题录；示例自动全文处理最多2篇，控制网络和模型消耗。
3. 对开放 arXiv PDF 按固定来源下载；失败时保留题录、生成部分完成记录。用户可以随后按论文上传合法 PDF，或仅运行单篇全文任务。
4. PDF 解析始终通过受限子进程执行；结果绑定论文ID、账号和 SHA-256。扫描版、复杂表格或超过资源配额的 PDF 可能无法得到可用全文。
5. 云模型仅当用户显式勾选、服务器已配置密钥时调用。未授权或无法调用时仍可建立全文索引，但不宣称得到完整结构化实验结果。
6. `validate_experiments` 核验逐字引用、数字、指标、数据集和条件。缓存重复分析，PDF 替换时清理/阻断旧结果。
7. 综合报告汇总本主题有效原文证据和明确标注的用户导入资料；仅列出比较候选，并提醒核对数据划分、指标定义与统计条件。

## 四、持久化数据库与升级

- `portal_auth` 新增迁移版本 4，向 `portal_jobs` 补充任务类型、论文标识、选项和阶段字段。
- `portal_workspace` 新增迁移版本 2，保存 PDF 文件摘要、按页文本和受控的实验证据。
- 旧版已签发的迁移记录校验摘要不可被修改。首次启动使用事务迁移，旧账号、会话和主题内容保留；发布前备份全部数据。
- 服务进程同一数据目录采用排他锁，避免双实例误消费。此机制仅适用于单机单实例，未实现跨机器的 worker 租约。

## 五、安全与稳定性验收范围

| 验收主题 | 本轮已有测试 | 仍未验收 |
| --- | --- | --- |
| 认证授权 | 两账号隔离、管理员/普通账号权限、Origin/CSRF | 真实浏览器与 HTTPS 代理下的端到端 SSO/会话兼容 |
| 文件安全 | 不受信路径拒绝、按账号隔离、文件大小、指纹失效 | 恶意 PDF 语料模糊测试与独立容器隔离 |
| 模型输出 | 幻觉数值拦截、无密钥降级、缓存 | 真实模型对复杂论文表格的精度与费用 |
| 任务稳定性 | 排队、服务恢复、取消、部分完成 | 高并发、系统 OOM、跨主机队列与强制 kill |
| 数据安全 | SQLite 迁移、只读 HTTP 检查、独立备份校验工具 | 真实服务器灾备恢复和定期异地备份 |
| 网络安全 | 固定主机 HTTPS 源、回环绑定、安全响应头 | 生产 Nginx、TLS、DNS、CDN、反机器人与 WAF |
| 自动更新 | 既有签名更新器保留 | 生产私钥 Release、Windows 实机更新与回滚 |

## 六、重大限制与上线门槛

1. 后端基于 Python 标准库 HTTP Server 和单机 SQLite 队列：适用于受控用户规模。大规模公网开放前，应迁移到经过生产验证的 ASGI/WSGI 服务器、独立 worker、任务租约、集中数据库及外部限流层。
2. 子进程 PDF 解析具有资源边界，Linux 采用 `resource` 配额；Windows 下只有父进程超时等机制，没有同等级操作系统级容器隔离。
3. 逐字引文有效不能证明科研解释合理；复杂表格、分组对照和多行数据关联仍需人工审查。
4. 当前只提供用户名密码注册，缺少邮箱验证、找回密码、验证码及滥用风控。建议先限制注册或采用邀请制灰度上线。
5. 云模型 API 配置由服务器运营方管理，用户不能通过公网接口提交任意模型 URL 或密钥。管理员应给用户明确的文字上传与费用提示，且不要对私有/受限论文默认发送全文。
6. Python/JS 单元与 HTTP 自动化测试结果不能替代真实公网安全审计或负载测试。签名发行必须由已有受信公钥对应的离线生产密钥执行。

## 七、下一阶段独立研发计划

- P0：上线硬化：密码重置、邮箱验证、Captcha、请求审计、外层代理 IP 限流、自动安全补丁检查；真实 Nginx HTTPS/备份恢复/断电验收。
- P1：任务引擎：Web 和 Worker 拆分；PostgreSQL 队列或具备租约的任务系统；重启幂等、进度与成本归属、多节点扩容。
- P1：科研质量：真实 PDF 标注集、表格结构识别、基线对齐、数据集定义和单位核对；评价证据准确率、漏检率与成本。
- P2：跨论文研究进展：时间窗口与综述模板、证据图谱、研究主题级智能问答及 Zotero 授权同步。
