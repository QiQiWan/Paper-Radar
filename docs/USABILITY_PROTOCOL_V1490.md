# Paper-Radar v1.49.0 普通科研用户可用性试验方案

## 研究目标与边界

观察没有软件开发经验的科研用户，能否独立完成模型连接引导、找论文、PDF 阅读、原文定位、自动跟踪和报告查看。关注实际用时、误操作、求助、放弃和术语理解问题。本版已经完成隔离环境中的浏览器自动化检查；**尚未招募真实参与者，暂无真人任务成功率或平均用时**。不得用自动化脚本秒数代替人的操作时间。

## 参加者与场景

拟招募至少 5 名未参与系统开发、平时有阅读文献需求的研究生、教师或研发人员，其中至少 4 名无编程经验，另可设置 1 名熟悉软件的对照用户。参加者自愿参加，允许随时退出。请使用预先创建的测试研究主题、开放论文和示例 PDF，禁止使用真实 API Key、含未公开研究资料的论文或个人账号进行屏幕录制。管理员须事先确认演示数据、离线检索缓存、网络与 PDF 可用状态。

## 试验组织

1. 测试者独立阅读一段简短说明，研究主持人不演示按钮位置，仅在参加者主动求助或软件不可操作时提供帮助。
2. 将 `tools/usability_study_v149.html` 单独打开并保留在一个标签页，在另一个标签页打开系统。该记录页完全本地运行，不通过网络上传测试结果。
3. 按 T1–T6 顺序开展每项任务；每项点击“开始计时”，操作系统，完成或放弃后填写“错误操作次数”“求助次数”“最让你犹豫的一步”，点击“结束并记录”。
4. T1 查论文；T2 理解模型连接（无需支付或购买密钥）；T3 设置每天自动跟踪；T4 打开并定位一份已有 PDF；T5 用中文问题查找 PDF 页码与原文；T6 查看和导出已有报告。每项任务说明以 HTML 原文为准。
5. 结束后导出匿名 CSV。测试主持人汇总 5 人的数据，记录关键阻碍，并在重新设计后重复对照试验。单个用户真实完成时间与自动化脚本执行时间需分别统计。

## 衡量指标与建议门槛

| 指标 | 计算方式 | 拟采用的验收目标（需真人验证） |
| --- | --- | --- |
| 核心任务完成率 | 完成任务数 / 所有任务数 | ≥ 80% |
| 无求助完成率 | 求助次数 = 0 且完成的任务比例 | ≥ 80% |
| 首次检索用时 | T1 操作时间中位数 | ≤ 5 分钟 |
| 模型配置理解 | T2 能清楚指出 Key 申请位置、粘贴位置及授权影响 | ≥ 4/5 人 |
| 页码定位成功率 | T5 是否能跳转正确 PDF 原文页 | ≥ 4/5 人 |
| 误操作 | 每个任务点击错误或进入错误页面的次数 | 记录真实值，优先处理高频步骤 |

这组门槛是产品设计目标，未得到任何参与者数据支持。错误操作、提示不理解、跨页面反复寻找、被迫联系管理员等均需归因到具体界面位置。模型服务商费用和平台登录问题单独统计，避免将外部服务无法访问误算为本系统按钮操作失败。

## 试验记录与分析

文件 `tools/usability_study_v149.html` 导出列：`id, experience, task, seconds, status, errors, help_requests, notes`。测试结果只包含匿名编号与任务级指标，不收集关键词内容、论文全文、IP 地址或模型密钥。建议形成逐任务统计表：成功/部分/失败人数、用时中位数与四分位距、错误次数总量、求助人数、最常出现的 3 类误解。对每个失误给出截图定位和修复项。保留试验版本号、浏览器版本与预置数据条件，便于改版后重测。

## 当前已有的自动化代理结果

- `tools/qa_v149_journeys.py`：隔离 Chromium DOM 与真实测试 HTTP/SQLite 的 20 项操作链路已通过；它测试接口及页面行为，不能代表真人理解难度，也不覆盖真实公网导航、Cookie 或支付模型 API。
- `tools/qa_v149_layout.py`：本地和公网版 5 个核心页面分别在 1440px 与 390px 宽度检查，共 20 组无横向溢出；不代表无视觉认知负担。
- 试用记录网页经 Chromium 自动执行“开始→结束→导出 CSV”验证；该数据仅用于证明工具有效，不能作为用户研究样本。

## 待补充的正式现场证据

真实参与者匿名数据（至少 5 人）、现场观察笔记、发生困难的页面截屏、成功率与用时中位数、修复前后对照。未形成这些证据前，版本只能标记为“自动化流程可执行；真人可用性未验证”。
