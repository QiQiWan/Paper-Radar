# v1.46.0 PDF 原文双盲标注与仲裁工作台

## 数据集与角色

工作台使用固定的 **30 篇真实预印本 PDF** 和 **256 个评估任务**（117 条单篇实验证据、88 个研究问答、34 个跨论文方法比较、17 个潜在冲突判断）。每条任务与原始文件 SHA-256 绑定。PDF 版权各异，**默认不在发布压缩包中重新分发原始 PDF**；通过官方链接下载并进行 SHA-256 校验。

四个凭据按角色分别发给**不同的实际研究人员**：
- **A 标注员**：阅读原始 PDF 并独立提交标注，看不到 B 的记录；
- **B 标注员**：与 A 独立标注，不能查看 A 的记录；
- **仲裁员**：两人都提交后才能同时查看 A/B 意见，核查 PDF 后给出不可修改裁定；
- **审计员**：只读审核进度、审计信息，不能代替他人提交。

大模型、自动生成的候选答案和来源中的预填 `answer_candidate` 不计入人工核对，也不会出现在标注员答案区域。所有数据仅保存在本地 SQLite，服务绑定到 `127.0.0.1:8778`。如团队需要远程协作，须部署有身份认证、TLS 和权限审计的独立服务；当前 localhost 工作台不能直接开放公网。

## 安装与启动

1. 解压 v1.46.0 完整源码到新目录，保留原有科研库数据备份。确认 Python >=3.10 与 `requirements.txt` 已安装。
2. 将上一轮从官方 arXiv 下载并通过 SHA-256 校验的 30 篇 PDF 放到 `benchmarks/real_pdf30/pdfs`。如已有其他目录，可在命令后添加 `--pdf-dir /path/to/originals`。
3. 首次创建独立标注库：`start_windows.bat --review-init`（Linux/macOS 使用 `./start_macos_linux.sh --review-init`）。终端只输出一次四套随机凭据，分别安全转交实际审核人员。不要拍照放到公开仓库，不要把凭据放进源码 ZIP。
4. 启动 `start_windows.bat --review`，浏览器访问 `http://127.0.0.1:8778/`。登录 A/B 账户、选任务、通过内置 PDF 浏览器核对物理页码和原文，再填写字段。
5. A 和 B 完成后，仲裁员登录并检查冲突或一致项。审核确认前不存在正式科学质量金标准。
6. 查看进度 `start_windows.bat --review-status`；生成审计快照 `start_windows.bat --review-export`；**只有全部 256 项都完成 A+B+仲裁，且 30 篇原始 PDF 全部校验通过时**，`start_windows.bat --review-gold` 才能导出用于评测的正式 CSV。

CLI 等价入口：`python -m paper_radar.review_webapp init|serve|status|export|export-gold --dataset benchmarks/real_pdf30 --db .paper_radar_home/realpdf30_blind.sqlite [--pdf-dir /path]`。本地其他工具仍由统一的两个平台入口启动。

## 标注字段

单篇实验证据要求证据标签、方法、指标、数值、单位、数据集、工况、基线、PDF 物理页码和原文。非实验证据应说明为什么是引文编号、图轴、学习率或其他错误候选。

跨论文比较与冲突任务需要分别给出两篇原文的页码与引文，以及同数据集、同指标、同工况的判断；不能仅凭数字相反就宣称实质冲突。对无法判断的项目选择“证据不足”，并说明需要的补充信息。

研究问答必须有可定位原文和支持理由。页面会强制检查关键字段、原始 PDF 哈希与引文是否能在相应页定位。

## 数据保护与可信评估边界

- 标注与仲裁写入数据库后不可覆盖，审计表采用顺序哈希链；输出的审计快照带文件 SHA-256。
- A/B 在相互不知道答案时提交；仲裁员在两人完成之前不会显示任何一方的判断。
- 本版本初始正式双人金标准数量 **0**，无法凭自动化代码“完成两名真实人员的标注”。
- 完成 A/B/仲裁，只代表科研任务参考答案已核查。若要评价模型生成回答的科学准确率，还需运行统一模型预测并对预测进行独立人工评价；不要把检索召回率当作回答准确率。
- 数据源、提示词、模型 ID、温度、上下文 Token、答案 Token、总预算和原文哈希需要在评测报告中固定。

## 验收覆盖

已有自动化测试覆盖固定数据集任务数、凭据隔离、HTTP 会话和 CSRF 防护、PDF SHA 与引文页码校验、不可修改的双盲提交和仲裁、审计哈希链（包括阻止通过直接插入 SQLite 行伪造审核）、以及未完成时禁止导出金标准。请使用实际两名研究人员完成端到端人工验收后再作为正式评估集使用。
