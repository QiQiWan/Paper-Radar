# Paper-Radar v1.23.0 — 复杂 PDF 解析与多批次断点续跑

本版本将公网解析能力扩展到最多 32 MiB、120 页，允许从文中较靠后的实验章节选择候选页，并为每批云模型调用写入可恢复的检查点。对纯文字 PDF，保留原先的 pypdf 回退路径；安装可选 PyMuPDF 后可提取部分表格行列候选，供 PDF 右侧核查界面查看。可配置使用本地 Tesseract OCR 处理最多 8 个低文本密度页面，默认关闭。

**科研边界：** 自动识别的表格行列是定位线索，不能直接当作已确认的实验归属。API 仅传输有界 PDF 原文候选页；本地 OCR 不向外传输 PDF。云分析仍需要用户主动授权。

## 修改范围

1. PDF 上限 12 → 32 MiB，Nginx 的 `/api/public/pdf` 单独使用 34m 请求体限制；每账号 PDF 总容量上限 360 MiB，保持总文件数限制。
2. 子进程 PDF 解析最多 120 页，正文最多 440,000 字符，每页 7,200 字符；子进程受 90 秒挂钟、Linux 地址空间与 CPU 预算约束。超额/异常需清楚返回失败，不允许无限运行。
3. 表格结构候选限额 60 张表、480 行，行的单元格来自可选 PyMuPDF 的 `find_tables()`；行列索引保留在工作区数据库，仅当前账号和原 PDF SHA 可读取。没有 PyMuPDF 时仍可提取普通正文；不暗中联网安装解析工具。
4. 云分析最多 12 页、每批最多 4 页，只有 JSON 响应及原文核验通过的批次会记录 checkpoint（包括零条有效结果）。调用失败之后重提分析，只执行未成功的批次；已完成的批次不重复计费。检查点绑定账户工作区、论文 ID、PDF SHA、模型配置、检索策略版本及该批次材料 SHA。
5. PDF 替换或索引版本变化会清除旧检查点，重新上传后不得复用旧证据。旧 PDF 索引缺少新式解析档案时自动重建，避免升级后遗漏布局候选。
6. PDF 预览支持 1—120 页，并可展开查看表格行候选；所有动态数据通过 `textContent` 呈现。

## 实际限制

- 某批成功的云模型调用之后、checkpoint 写入之前若进程崩溃，该批可能再次付费调用；现有 SQLite Worker 系统保证任务租约隔离，但不承诺第三方模型 API **exactly-once** 计费。
- 表格识别受 PDF 内容流、栏位和行线影响。扫图复杂表格和公式、图中曲线数字、扫描 OCR 精度需要人工核对。
- OCR 默认关闭。开启时设置 `PAPERRADAR_PUBLIC_PDF_OCR=1`，部署系统需另行安装 Tesseract；英文识别使用 `eng`，其他语言包由运维单独安装和授权。
- 可选 PyMuPDF 采用独立许可证（含 AGPL/商业许可要求）；发行包没有打包此库或 Tesseract。商业环境启用前应核对许可证与替代选项。
- 真实 FNO/U-FNO/PINO PDF 和云模型预测文件不随源码分发；缺少文件时真实论文解析召回率仍为“未测量”。

## 数据库与回滚

公网工作区数据库由 v5 向 v6 **追加迁移**：`pdf_layout_rows`、`pdf_batch_checkpoints`、`pdf_parse_profiles`。账号数据库维持 v6。必须停 Web 与全部 Worker、完整备份后升级；若回滚 v1.22.1，须恢复升级前用户工作区 SQLite 与文件快照。详情见 [升级手册](UPGRADING_V1.23.0.md)。
