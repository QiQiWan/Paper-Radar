# Paper-Radar v1.19.1 升级指南

适用版本：已运行 v1.19.0，保留原有研究库、账号、PDF、实验数据和运行任务历史。

## 升级前检查与备份

1. 停止公网 Web 服务和全部 `paper_radar.portal_worker` 进程；在 Linux systemd 部署中先停止 `paperradar-worker@...`，再停止 `paperradar-public`。
2. 完整备份环境变量 `PAPERRADAR_PORTAL_DATA` 指向的数据目录，至少包括 `accounts.sqlite3`、`users/` 及 PDF/工作区文件；同时备份桌面端 `settings.json`、`data/`、`downloads/`、`reports/`。
3. 检查备份能读取，并确认磁盘有充足空间。生产端请在本地留存升级前原程序代码。
4. 停机状态下更新源代码；勿覆盖已有的数据目录。按部署手册使用同一个 `PAPERRADAR_PORTAL_DATA` 启动 Web 与 Worker。

## 数据库迁移

首次运行时按注册表自动迁移：账号库 `portal_auth` v5→v6，新增任务阶段表；用户工作区 `portal_workspace` v2→v3，新增历史报告表。系统会检查迁移版本与校验摘要；旧程序无法直接读取高版本数据库。发生问题时必须同时恢复旧代码与升级前完整数据备份。

## 验证顺序

1. 运行 `python -m pytest -q tests`，确认所有自动化测试通过。
2. 启动公网 Web 与独立 Worker；检查 `/api/public/health`，并确认只有预期的公网 API 对外开放。
3. 以普通用户登录，打开当前课题，提交一次范围较小的检索/研究任务；确认任务详情出现新的阶段记录。
4. 等任务完成，点击“研究报告与历史”下的“在线阅读”，检查正文和原文引用，下载 Markdown。
5. 刷新页面后重新打开同一份历史报告，确认报告内容不变、不会再次触发模型 API 调用。
6. 用第二个测试账号尝试访问第一个账号的报告 ID 和任务 ID，应返回 404；退出登录访问应返回 401。
7. 在 390px 移动端检查任务摘要、历史报告和表格局部滚动。

## 异常排查

- **任务长期排队：** 检查 Worker 服务是否运行、两端数据目录是否一致，以及 Worker 是否拥有对应目录读写权限。
- **旧任务看不到阶段：** 升级前的历史任务未记录事件，属于预期行为。新版任务会写入阶段。
- **报告没有历史记录：** 既有动态报告不会被自动改写成快照；提交一次新的研究或综合报告任务。
- **报告过大：** 单份报告的 Markdown/摘要存在大小上限，请收缩课题范围重新生成。
- **回滚：** 先停止 Web/Worker，恢复旧代码与升级前数据库及用户工作区备份，再启动旧版。

## 重要说明

该源码 ZIP 尚未使用部署者持有的生产 Ed25519 私钥签署正式 GitHub Release。旧客户端的可信自动安装流程仍须正式发布者创建匹配的三件套发布附件后才能使用。不要把开发 ZIP 直接当作可信的线上升级附件。
