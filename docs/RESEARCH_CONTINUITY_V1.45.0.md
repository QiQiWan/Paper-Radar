# v1.45.0 持续科研智能体：实现与验收

适用范围：Paper-Radar v1.45.0 集成验证版。基线为 GitHub 正式发布的 v1.40.6 源码产物。首次升级前应备份数据库；新增的 SQLite 迁移具有前向兼容设计，旧版本不会认识新增表和版本号，不能直接以旧程序覆盖后继续修改数据库。

## 一、长期记忆和人工反馈

每个研究主题独立保存个人笔记、研究问题、工作假设和已确认结论四类研究记忆。研究人员可编辑、归档，但系统保留不可修改的版本历史及操作记录。将某段文字标为“已确认结论”时，必须关联一条当前有效的人工确认结论，并使用原文一致的正文；模型解释和个人猜想只可保存为“工作假设”或其他人工记录。

记忆同时保存结论 ID、修订号及正文签名。源 PDF 替换、原文锚点失效或者人工修订结论后，关联的确认型记忆自动变为“需复核”。已归档内容不能被旧的编辑请求重新激活。用户在论文库对论文作“相关/不相关”反馈，记录在独立表中；系统据此生成可解释的关键词偏好，只对已经通过主题相关性筛选的候选论文进行轻微重排序。它不会改变时间窗、检索来源或原始论文记录。

## 二、研究进展与周期简报

当已有 `following_events` 记录论文新增/更新事件时，程序可以形成上一完整自然日、自然周或自然月的研究简报（统一采用 UTC）。内容包括新增与修改的题录事件、前一报告和当前人工确认结论的增删修订、待补检来源、偏好反馈和下一步待核查问题。

新增论文的题录事件标记为 `metadata_only`。这些事件只能提示研究人员进一步阅读全文；是否属于领域突破取决于后续取得的原始实验证据。模型解释作为可选的手动增强任务，调用前需要明确授权；周期性自动生成默认关闭，也不发送任何模型请求。

“检索完成后自动生成”是一项触发方式：只有用户开启该功能，且完成一轮成功入库的检索，才会检查是否需要生成上一完整周期简报。目前还没有独立的系统定时器主动在周一生成报告；需要安装现有检索计划任务并保持检索工作流正常执行。

## 三、存储和运行

新增 `research_memory_items`、`research_memory_audit`、`research_interest_feedback`、`research_brief_preferences` 和 `research_period_briefs`。研究记忆版本采用乐观锁；审计表和历史简报通过数据库触发器禁止修改/删除。相同主题、相同周期、相同结束时间重复生成简报时复用历史快照；再次打开会检测 PDF 与人工结论是否已发生变化。

本地版由 `paper_radar/research_continuity.py` 实现，`agents/pipeline.py` 在主检索完成后执行一次有界的、不会改变主检索结果的简报触发检查。公网版在账户空间内独立执行同样的确定性功能。模型 API、Zotero 凭据、PDF 以及用户私人笔记不会因为自动简报而发送到公网模型。

## 四、使用方法

1. 在“研究助手”→“科研综合与持续跟进”→“研究记忆”，保存具体研究问题、人工笔记、待验证假设；确认型记忆需要原文确认结论 ID。
2. 在综合报告的原文证据卡片下标记“相关”或“不相关”，后续本地检索会使用这一反馈作为小幅排序参考。
3. 在“周期简报”选择每日/每周/每月。首次启用自动生成时勾选选项并保存；如果只需本次简报，可直接按按钮手动生成。
4. 对照“新增论文”“已确认结论变化”“待验证问题”，逐项打开 PDF 核查。报告可下载 Markdown，历史版本不可覆盖。
5. 如报告提示“证据需复核”，应回到该主题的已确认结论与 PDF 查看变化。

## 五、边界与待验收项

- 兴趣学习目前采用可解释的词项权重，属于轻量化反馈；尚无长期在线强化学习或真实用户多周效果评测。
- 研究趋势分析限定在当前系统已成功检索并保存的事件和已确认结论范围，不代表全学科覆盖。
- 历史简报存在最大事件处理预算，超出范围会给出截断提示；规模化补检需下一阶段增加按时间窗的任务队列。
- 新增/修订对比依赖前一个周期的已保存快照。首次运行时没有旧快照，会将当前有效的确认结论列作初始基线。
- 真实研究效果需要连续多周数据和人工复核，当前没有经过验证的“节省多少小时”或“发现了多少研究空白”等数据。

## 六、验收项目

必须检查主题隔离、账户隔离、CSRF/本地 Token、防止记忆记录越权、PDF 失效提示、历史不可变、UTC 跨月/跨年周期、简报幂等、重复任务、用户反馈不改变论文检索结果、默认无云调用、授权失败回退。发布前还需使用真实 PDF 完成至少一个跨论文综合案例和一个跨周进展案例。
