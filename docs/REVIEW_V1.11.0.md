# Paper-Radar v1.11.0 深度优化与验收报告

**日期：2026-11-04**  
**基线：v1.10.0 源码压缩包**  
**实施版本：v1.11.0**  
**测试说明：** 以实际代码文件为审查对象。部分接口测试使用模拟数据；未拥有用户的真实 OpenAlex 额度、出版社订阅账户、云端模型密钥与 Windows 工作站。

## 一、核心判断

v1.10.0 的检索、Zotero 和报告能力已经形成基本工作流程。其主要结构问题是多个研究主题共享论文层面的星标与阅读状态，无法支撑长期个性化推荐。本版优先完成论文元数据与主题评价分层，增加模型证据约束排序、可选语义发现、多主题批量调度和运行历史。保留 SQLite 与现有 Web 工作台、下载器和报告接口，避免不必要的重写。

## 三、回归测试结果

测试覆盖 v1.10.0 原始用例以及新增的 v1.11.0 功能测试。具体数量和运行环境以随包附带的 `TEST_RESULTS.md` 为准。重要测试场景：

1. 旧版 `papers` 字段迁移到默认主题，不删除原始用户标记。
2. 原有半升级 `topic_papers` 缺少新字段时自动迁移。
3. 同一 DOI 对应统一文献元数据，但两个主题能够分别星标、已读和反馈。
4. 正反馈仅提高本主题排序；负反馈仅屏蔽当前主题的近期阅读推荐。
5. 模型推荐无原文依据、错误类型 ID、无效等级或请求失败时不得提高论文分数。
6. 已验证的结果在同一主题和模型下可以复用；不同主题不会共享个性化缓存。
7. OpenAlex 语义查询默认关闭，若主动开启则使用受限请求，错误权限/限流有明确异常信息。
8. 多主题顺序追踪后，单主题失败不阻断其余主题；全部失败则返回错误。
9. 任务历史未存储原始敏感研究正文与 Key，且查询可以按主题隔离。
10. 版本号、文档、JavaScript 和 Python 源码保持同步。

本地 Python HTTP 健康接口曾成功响应 `{"app":"paper-radar","version":"1.11.0"}`。该环境中的 Chromium 被策略阻止直接访问 `127.0.0.1`，故页面交互通过包含真实 HTML/CSS/JavaScript、模拟 HTTP 接口的离线渲染方式检查，不能把这一结果理解为 Windows 端到端浏览器验收。

## 四、可用性与质量边界

**可以确认：** 主题隔离数据读写、结构化推荐证据核对、任务调度逻辑、配置迁移和离线页面渲染受自动化测试覆盖；语义来源采用显式可选方式，模型失败不会中断基础检索。

**尚未确认：** 真正新增多少高价值论文、哪家模型推荐最好、OpenAlex 的实际费用、不同版本 Zotero 兼容性、PDF 批量下载的稳定性和 Windows 计划任务实机运行情况。推荐理由的连续原文证据只能验证其引用存在，不能证明模型的学术解释完全正确。

**仍有设计空间：**

- 构建人工标注集，定量比较 v1.10 与 v1.11 的 Precision@10、Recall@50、NDCG@10。
- 对同一论文的预印本与正式发表版本建立版本关系，增加会议接收状态审查。
- 加入可选 Embedding / reranker 的混合检索，与现有确定性结果进行可解释加权。
- PDF 解析阶段保存每一条方法和数值结论的页码、段落与表格位置。
- 添加按论文处理步骤的断点恢复、资源用量预算、PDF 下载队列以及多操作系统定时任务安装体验。
- 现有接口仅限 localhost；如需多人协作、远程访问或云端部署，必须另行进行认证、权限、版权和备份架构设计。

## 五、实际使用建议

升级前完整备份 `settings.json`、`data/`、`reports/` 和 `downloads/`；在新版本完成一次默认主题检索后，再分别运行旧版已建立的其他研究主题。建议先关闭 AI 推荐与 OpenAlex 语义发现，确认普通检索及报告正常，然后在 API 有额度的前提下逐个开启并比较质量。出现“部分完成”时，应检查每个主题的任务历史和来源执行记录，避免将结果当作完整检索覆盖。
