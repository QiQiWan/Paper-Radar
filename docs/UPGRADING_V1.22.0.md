# Paper-Radar v1.22.0 运营部署与研究任务验收清单

本清单适用于 v1.21.2 或 v1.21.1 的现有公网工作区升级。所有实际运维操作均需有登录服务器和数据备份权限的人员执行。

## 升级前

- 确认当前程序、账号库及每个账号的工作区数据库和 PDF 目录均已备份。避免备份时 Web 或 Worker 正在写数据库；可以先停服务后使用 `python tools/public_backup.py` 按工具帮助操作。
- 记录原有 Nginx 配置，确定 `/api/public/pdf` 使用 13m 请求体限制，其他业务接口采用较小请求体上限。
- 若版本来自旧的发布签名程序，确保后续正式发布流程具有当前生产密钥、发布清单和校验机制。此处独立交付的源 ZIP 仅适合人工审核和受控安装。

## 升级后人工验证

| 步骤 | 触发操作 | 期望观察结果 |
| --- | --- | --- |
| 1 | 登录两个独立账号，分别建立研究主题 | 论文、PDF、历史任务和报告互不可见 |
| 2 | 在断网环境触发检索并取消 | 检索在来源超时/取消预算内返回，页面恢复可交互 |
| 3 | 上传正常 1–10 MiB PDF | PDF 上传成功，进入索引流程，未突破后端 12 MiB 限额 |
| 4 | 上传超 12 MiB PDF | 服务器拒绝并给出明确说明，无残留未核实证据 |
| 5 | 在前 8 页以外包含实验表格的 PDF 上授权模型分析 | 任务详情展示候选物理页；若模型提取合法引文，可点页码打开原文 |
| 6 | 临时撤销模型配置或使模型不可达 | PDF 保留，任务显示“部分完成”并说明原因，不误称“实验数据缺失” |
| 7 | 检查 24 小时剩余额度 | 检索、PDF 分析、报告生成、云模型调用独立统计 |
| 8 | 使用两篇确有一致评价条件的论文生成报告 | 系统只展示人工比较候选，提供基线、量纲等复核项目，无推测的提升百分比 |
| 9 | 连续完成三个批次、再次分析同一 PDF | 第二次命中缓存，不增加模型调用额度 |
| 10 | 关闭 Worker 后恢复，检查任务历史及报告快照 | 旧报告可查看，取消与超时反馈与数据库一致 |

## 研究质量验收

报告 `real_paper_eval.json` 中需明确区分以下数据：

- PDF 实际解析数、原文锚点定位数（实际 PDF 提取质量）；
- 候选页覆盖率与候选片段锚点覆盖率（检索召回质量）；
- 来自真实模型预测的 Precision、Recall、F1（只有提供预测输入才测量）；
- 可比与不可比标注的准确率及错误分组率（当前 3 篇真实种子集只有不可比关系）。

在实际扩充至多样论文和足量可比正例之前，不能报告“学术分析准确率达到某个百分比”的已验收结论。人工核查包括 PDF 版本、实验条件、基线、单位、指标方向、统计显著性及 OCR/表格跨行问题。
