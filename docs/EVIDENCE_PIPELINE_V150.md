# Paper-Radar v1.50.0｜批量 PDF 证据准备与跨论文实验对照

## 适用范围

本轮面向**本地工作台的研究分析页**，复用现有本地 SQLite 文献库、公开访问 PDF 下载、PDF 全文索引和人工证据验证能力。公网多用户平台尚未接入这套批量任务，需完成按账号隔离和 Worker 调度后再接入。

流程：研究问题 → 筛选最多 12 篇高相关论文 → 逐篇获取公开 PDF → 本地解析并按页索引 → 提取实验候选 → 集中核对 → 查看已确认数值的跨论文对照。

## 研究人员如何操作

1. 进入「研究分析」，输入一个具体研究问题，例如“神经算子在不同网格和几何形状下的泛化实验有哪些结果及限制？”
2. 点击「选择相关论文」。系统仅按当前研究主题的已收录题录筛选，展示相关度理由和本地是否已有 PDF；可取消不想处理的论文。每批最多 12 篇。
3. 点击「开始批量准备」。默认只在本机进行 PDF 下载与全文解析。如果已连接模型且明确同意发送本批所选论文的有限原文片段，可开启结构化实验抽取。模型服务可能产生费用；未配置或关闭模型时，系统只提取可定位的本地实验原文片段。
4. PDF 下载、全文读取、实验候选生成按论文**顺序**执行。单篇文件缺失、无法解析或模型异常不会阻断其他论文。查看「每篇论文的处理进度」可定位异常；通过「继续未完成任务」「重试未提取的论文」恢复任务。
5. 在「待人工确认的实验片段」中核对 PDF 页码、原文和指标。数据集、指标、数值、对照方法、实验条件均应在相应引用片段中**原文出现**；填好说明后点「核对后确认」。排除不适用片段时点「排除这条」。如果原文已被其他研究结论引用，系统拒绝直接撤销并提示先解除引用。
6. 点击「查看跨论文对照」，查看两篇及以上论文在**同名数据集、同名指标**下已人工确认的并列记录；可导出 CSV。每条记录包含 PDF 原文、页码与文件指纹。研究分析页面历史报告也会动态显示相关的已核对实验数值。

## 用户界面中的状态解释

| 状态 | 含义及处理 |
|---|---|
| 等待处理／处理中 | 后台正在准备证据，刷新页面可恢复当前批次 |
| 无开放 PDF | 论文来源无法直接提供可下载 PDF；可到论文网页或手动上传授权版本 |
| 全文不可读 | PDF 可能是扫描件、乱码或加密文档，需换有文本层的版本；本轮不新增 OCR |
| 未检出实验数值 | 已读出全文，但没有可靠的数值实验片段；可使用模型抽取、重新下载或人工检查 |
| 可审核 | 已获得和 PDF 页码绑定的候选；**尚未通过人工确认** |
| 模型未连接 | 后台执行本地原文候选提取；不会虚构模型生成成果 |
| 模型提取失败 | 已记录模型失败状态，优先保留本地原文候选；可导出诊断日志 |
| 已确认 | 研究者核对了连续原文和指标数值，记录绑定 PDF 指纹 |
| 引文失效 | PDF 文件改变、文本索引更换或原文定位失败，旧确认不再进入对照 |

## 科研解释边界

- **题录相关性**仅决定待下载的阅读顺序，不支持任何科学结果判断。
- **自动抽取候选**通过原文逐字匹配和页码检查之后进入人工队列；未经确认不进入正式实验数值对照。
- **人工核对的实验数值**支持原文出处和字段核查，不直接证明不同论文结果可比。跨论文的指标定义、归一化方式、样本划分、随机种子、训练预算和边界条件仍需研究者确认。
- 不自动计算“领先百分比”“一致性结论”“统计显著性”，避免在实验设置不相同时比较数值大小。
- 表格跨行、扫描件以及多栏 PDF 的解析仍可能丢失关系。系统保留原文片段和页码，不能把模型提取结果当成真实实验结论。

## 技术实现（维护人员）

`paper_radar/evidence_batch.py` 保存四张本地 SQLite 表：`evidence_batch_runs`、`evidence_batch_items`、`evidence_batch_candidates`、`evidence_batch_events`。批次包含运行编号、主题、研究问题、模型请求状态以及时间；每篇论文有独立阶段与失败次数；候选包含 PDF SHA256、chunk_id、页码、连续引文、结构化字段、审核版本号和人工说明。

可调用 API：

- `POST /api/evidence-batch/preview`：研究主题内选题预览，限制 12 篇
- `POST /api/evidence-batch/start`：创建任务，显式确认模型数据发送
- `GET /api/evidence-batch/status?run_id=`：跨刷新恢复队列、阶段与审核记录
- `POST /api/evidence-batch/resume`：重置失败/中断子任务，不覆盖已确认结果
- `POST /api/evidence-batch/review`：乐观锁审核，必须匹配当前 PDF 指纹及原文
- `GET /api/evidence-batch/compare`：仅返回当前有效的人工确认记录
- `GET /api/evidence-batch/export`：UTF-8 BOM CSV，防止公式注入

POST 仅接受来自本机并携带本地 Token 的 JSON，已有 Host/Origin 检查继续生效。

状态推进采用单线程逐篇处理；不把文件下载错误转化为整个批次失败。同一 PDF 版本与片段的候选有稳定内容哈希；重复执行不会重复创建，同一未经审核的记录可以由最新批次接手。审核和对照读取时再次校验 PDF 指纹。单次状态读取中每篇 PDF 的摘要只计算一次，避免大型队列重复扫描文件。

模型可用性从用户配置与授权判断。导出的任务记录包含模型状态（未请求、不可用、结构化结果、失败回退、未产出结构化结果等），不能仅凭 HTTP 202 或“任务已结束”推断 AI 完成科研分析。

诊断 ZIP 新增 `evidence_batches.json`，只含运行编号、阶段与状态计数、不含研究问题、标题、PDF 正文或 API 密钥。支持中途下载。

## 运行、恢复和升级

备份旧用户数据后解压 v1.50.0 到新程序目录。使用原有 `start_windows.bat` 或 `start_macos_linux.sh` 启动。保留现有数据目录，首次打开研究分析页会创建批量任务表；不会自动下载或发送科研内容。不要把测试目录内的 SQLite 或生成 PDF 覆盖至正式工作目录。

后台异常退出后，重新启动，回到研究分析页即可读到最近批次，选择「继续未完成任务」。外部学术网站下载可能受版权、机器人策略、限流或网络限制；本轮自动下载仅使用已有的受限开放获取下载器。

## 验收与后续工作

本轮使用隔离生成的真实 PDF、SQLite、HTTP API 和浏览器组件对批量准备、失败隔离、重试、人工审核、原文证据与 CSV 进行测试。仍需在用户电脑上验证 60 篇真实文献的 PDF 可获取率、复杂表格解析效果、真实模型费用与有效字段提取率。后续优先完成原生浏览器端到端验收、真实论文双人盲标、复杂表格与扫描件处理、公网按账号隔离的 Worker 接入。
