# Paper-Radar v1.21.2 — 公网检索故障收敛与 SQLite 负载收敛

## 检索故障恢复

公网 arXiv 入口改用 `paper_radar.sources.supervisor.fetch_isolated`，源适配器运行于独立子进程，默认 25 秒硬截止（环境变量 `PAPERRADAR_PUBLIC_SOURCE_TIMEOUT`，允许 2–90 秒）。超时终止进程并返回可读来源错误；取消任务时同样终止请求子进程，`JobCancelled` 不被错误转换为网络故障。

跨 Worker arXiv 全局文件锁和结束后访问间隔仍然生效；单次等待锁最多 35 秒，速率门控最多 20 秒。公网检索成功响应返回 `source_results`（源名、数量、耗时、子进程模式）。网络失败的错误不会泄漏底层请求 URL 或模型密钥。没有新增非 arXiv 公网来源；受认证/商业许可的适配器仍仅在桌面版提供。

## 数据库和队列

- 每个进程首次使用账号库/用户工作区时运行完整迁移及 checksum 校验；后续同一文件身份的请求免重复 `BEGIN IMMEDIATE` 迁移。新进程/新数据库文件仍重新校验。**进程运行期间外部篡改迁移表需要停止服务并人工审计，不能据此将该缓存当成完整篡改侦测。**
- 有效登录会话以最小 60 秒间隔刷新 `last_seen`；仍执行每次认证读取和有效期检查。任务历史中超过最短空闲失效时间的请求仍会被拒绝。
- Worker 空闲时的队列恢复频率限制为最多每 5 秒一次；显式 `recover()` 仍立即执行。Worker 空闲状态心跳有界写入，任务结束强制刷新最终状态。
- 任务中心展示不同工作任务的剩余额度；云端实际调用采用单独的模型配额。

## 验收边界

新增 `tests/test_v1212_stability.py`，原 arXiv 串行门控测试适配到隔离来源入口。CI 新增 `portal.js` 语法检查及 Windows 冒烟作业定义。需要在实际 Nginx、Windows、故障网站与并发负载上执行后才能声明生产稳定性通过。SQLite 多进程单主机运行，不能将该队列直接扩展到多节点网络文件系统。
