# Paper-Radar v1.21.0：网络故障恢复、全文精读与实验比较矩阵——设计审查

版本日期：2026-11-05。本文适用于 v1.21.0 的**实际代码交付**；图形设计和科研效果的边界分别列出。

## 一、结论与本轮范围

v1.20.0 解决了公网工作台五入口导航，但尚存在三个影响连续使用的问题。其一，来源网络不可达时，多组关键词查询叠加网络超时，页面长时间停留在检索中；原来的 Agent 协作检查只能在第三方阻塞调用返回后生效。其二，已经提取的实验引文和原始 PDF 分离，核查论文需切换页面或浏览器标签。其三，SynthesisAgent 已生成结构化比较结果，网页仍以 Markdown 为主，筛选和逐项核验不便。

v1.21.0 已分别添加独立来源子进程、按账号访问的 PDF 双栏阅读器，以及基于不可变报告快照的实验比较矩阵。桌面和公网继续使用各自的安全入口，保持已有五入口导航、独立 Worker、研究账号与报告快照不变。

## 二、故障定位与修复流程

### 2.1 已确认的机制

旧来源适配器在多个关键词上独立请求，同一个站点可能连续发生慢连接。部分适配器设置 30–35 秒 HTTP 超时并带重试。对源代理仅设置协作式 Agent 时间预算无法主动中断正在阻塞的 urllib 调用，导致进度停滞。

### 2.2 新的执行过程

1. DiscoveryAgent 构造**来源白名单**内的检索计划。生产检索调用 `fetch_enabled(supervised=True)`，每个单组查询交给 `python -m paper_radar.sources.source_process`。
2. 父进程将长度受控的必要检索参数经标准输入发送给子进程；模型密钥或出版社 API Key 不随任务 JSON 传输。由各来源适配器按原授权机制取得自己的权限信息。非固定来源不会被执行。
3. `supervisor.fetch_isolated` 按挂钟计时。每约 0.35 秒检查任务取消/Agent 截止条件，在等待超过 1 秒时更新剩余时间提示。默认单组 10 秒，整个来源发现阶段 75 秒。两项可在本地设置页调整，单组允许 4–60 秒，总预算允许 20–240 秒。
4. 单组超时后终止子进程并跳过该来源的其余关键词组；继续尝试下一个已启用来源。一个来源某些查询成功、某些失败，标记 `partial`。无论文结果但请求正常完成时仍标记来源可访问。
5. 所有来源均失败时抛出 `AllSourcesUnavailable`，携带源名称、成功状态、耗时和超时信息；Web 将状态写为 `failed`，任务进度结束于 100%，来源诊断可展开。整个失败流程不会生成虚假的成功报告。
6. 已有来源结果可用时，后续入库与报告继续执行，整次任务标记 `partial`，保留每个来源的故障诊断。

**取消与 Agent 截止**是全任务指令：`AgentCancelled` 和 `AgentDeadlineExceeded` 直接传播，不被降级为普通来源错误。不同网络供应商的真实超时仍需要 Windows/服务器联网环境重复验收；此版测试覆盖了完全不响应的子进程和任务取消。

### 2.3 异常恢复边界

| 情况 | 程序行为 | 用户操作 |
| --- | --- | --- |
| 单个来源 10 秒内不返回 | 终止对应查询进程，记录“超时，已跳过” | 可查看来源诊断，必要时缩减来源或修改超时 |
| 一个来源失败、另一个正常 | 继续入库并保留故障信息 | 可以使用已发现论文 |
| 所有来源不可访问 | 失败状态明确结束，保留错误及来源摘要 | 检查网络/代理/机构权限；离线仍可阅读历史论文 |
| 用户取消 / Agent 截止 | 向上报告并回收来源进程 | 根据任务状态决定是否重试 |
| 来源要求 API Key 或机构 IP | 沿用各来源授权流程；错误信息不携带访问 URL 与凭证 | 在设置中配置授权，或关闭该来源 |

**限制：** 对来源调用的墙钟预算只覆盖生产检索源查询。Zotero 文件读取、PDF 解析、云模型速览、Word 导出仍由原有独立模块治理；整次任务实际耗时可能超过来源发现阶段的 75 秒。公网 arXiv 独立任务仍使用其受控来源限频与短网络超时。

## 三、PDF 双栏阅读与访问控制

### 3.1 桌面模式

`论文库 → 全文证据` 展示左侧内嵌 PDF，右侧为当前引文与实验信息。用户点击证据页码可调整左侧 `#page=N`；Ctrl/Shift 新窗口操作继续使用浏览器行为，保留独立标签打开 PDF 的能力。证据来自原来已存在的全文索引和原文逐字校验存储。

### 3.2 公网模式

`GET /api/public/pdf/view?topic_id=<topic>&paper_id=<id>` 要求有效登录会话、用户在该研究主题拥有此文献、对应账号专属 PDF 文件存在，并核查文件 SHA-256 与数据库版本相同。响应 `Content-Type: application/pdf`，支持 `Range: bytes=x-y` 与 `206 Content-Range`，无效范围为 `416`；不可访问/旧版文件拒绝显示。大小沿用公网 PDF 上限 12 MiB。

只有 PDF 响应设置 `X-Frame-Options: SAMEORIGIN` 与 CSP `frame-ancestors 'self'` 以允许本系统双栏嵌入，其他网页仍是 `DENY` / `frame-ancestors 'none'`，并保留 `Cache-Control: no-store`。公网界面只构建自身的受控相对 URL，不从论文数据中拼接任意 PDF 路径。

科研用户在论文库点击“查看证据”，可以按页定位 PDF，同时显示该页已核验的结构化实验信息、逐字引文和原始文本。网页在手机端由两栏切为上下阅读，浏览器不支持 PDF 内嵌时提供新标签打开的链接。

**重要局限：** PDF 页面阅读器使用浏览器原生 PDF 能力，未实现自建 PDF.js。复杂表格、扫描版 PDF、公式和跨页排版的抽取质量并未因此获得改善；来源证据仍需研究人员核对。

## 四、实验比较矩阵

报告页 `renderComparisonMatrix(summary)` 读取已保存快照 `summary.comparisons`。每组以方法类别、数据集、指标和完整实验条件形成候选，按数据集或指标过滤。矩阵逐行展示标题、原文数值、对照基线、证据等级、当前页码和跳转入口。

- 已核验本地 PDF 的记录可以从矩阵直接进入对应文献证据窗口；用户导入但未核验的记录只显示待核查状态。
- 数据集和指标名称相同不足以证明结果可比：baseline 不一致、百分比表达不一致、缺失设置、数据划分未知等均作为风险标注。
- 矩阵**不自动排序模型、不计算跨论文性能提升百分比**；原始报告的 Markdown 正文和快照完整保留。
- 仅使用安全 DOM 文本构造展示研究文字、指标及原始引文，不把论文内容作为 HTML 运行。
- 宽表限定在局部横向滚动容器中；移动端 `.portal-page` 使用 `minmax(0,1fr)` 防止自动列宽被表格撑开。

## 五、与现有架构的兼容

- 不新增数据库 schema，也不改变 v1.20.0 的账号、报告、PDF 和任务历史结构。
- 保留 16 个 Agent、独立 Web/Worker、租约/心跳和已签名更新协议。
- 桌面检索源使用监督式子进程，非生产测试注入的 `fetcher` 保留原调用接口。
- 公网 PDF 访问必须绑定登录用户和研究主题；跨账号测试覆盖 401/400、文件变更 404 与 HTTP 范围请求。

## 六、验收标准与后续问题

技术验收：持续睡眠的检索子进程在截止后被终止；用户取消不能被当作来源失败；一个来源故障不阻断其他来源；全部来源失败有可读结束状态。报告候选矩阵保留页码、基线、证据等级，跨账号读取被拒绝。浏览器实际前端代码测试需要在 1440px 和 390px 均无 JS 错误和页面横向溢出。

上线前仍应验证 Windows 11 上的子进程退出、真实境内/境外文献源不可达场景、浏览器原生 PDF 插件、HTTPS 反向代理和大文件 PDF 多次字节范围加载。真实论文基准的 ExperimentAgent F1、PDF 表格召回率与 SynthesisAgent 可比性正例指标不在本轮声称已完成。
