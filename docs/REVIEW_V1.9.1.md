## 1. 核心结论

v1.9.0 已具备完整的基础文献追踪闭环：检索 arXiv、OpenAlex、Crossref，以及可配置出版社题录接口；Zotero 本地只读分析；星标与阅读状态；合法公开 PDF 下载；中文速览；Word/Markdown/CSV 导出；Windows 计划任务和本地 Web 工作台。这些已实现功能不需要重新设计。

核心缺口集中在四个方面：（1）关键词匹配无法充分理解科研问题，多来源检索词覆盖存在截断；（2）模型只参与摘要级中文说明，缺少独立的检索规划、重排序与全文证据链；（3）跨数据源同一论文更新可能覆盖更完整摘要及旧模型结论；（4）研究主题与历史知识尚未独立建模，无法长期追踪多个课题。

本轮 v1.9.1 主要解决立即影响结果真实性、使用体验和数据一致性的问题，同时引入**用户审查后才生效的 AI 检索词规划**。多主题、OpenReview、Embedding/RAG 和全文证据抽取属于下一阶段，不应标记为已实现。

## 2. 已验证的原版行为

| 范围 | v1.9.0 现状 | 审查判断 |
| --- | --- | --- |
| 学术检索 | arXiv、OpenAlex、Crossref 默认；Springer、Elsevier 可选 | 已形成基础数据链；同一主题查询覆盖不一致 |
| Zotero | Local API 与只读 SQLite；关键词、参考文献相似度 | 已有可用基础；自动覆盖手工关键词需明确控制 |
| 文献关联 | 使用 DOI 和 paper_id 合并；标题也可参与 Zotero 已收藏判断 | 同 DOI 更新存在可复现的摘要质量倒退 |
| 相关性排序 | 标题/摘要关键词评分、Zotero 传统文本匹配 | 暂无独立 BM25/Embedding 检索与 LLM 重排序 |
| 云端模型 | 多服务商；生成标题+摘要级中文速览 | 缺少持久化模型/提示词证据版本与量化结果校验 |
| 论文全文 | PDF 下载与失败重试 | 未进行章节、表格、公式和页码级结构化解析 |
| 报告 | Word、Markdown、CSV；主题总结与论文详目 | 证据来自题录、摘要和规则；全文结果无法核验 |
| 用户界面 | 本地六入口工作台、折叠高级选项、进度与日志 | 主要操作相对集中，模型功能仍偏隐蔽 |
| 多主题 | 一套当前关键词和一套计划任务 | 切换课题易覆盖当前配置，历史报告未按课题隔离 |
| 错误处理 | 来源失败可部分继续，下载可重试 | 缺少完整的跨来源配额/耗时/失败率监控 |

所附原版离线报告已将岩土主题的30条候选记录筛为3条，其中1条只有题录；该数据来自先前的离线复核，尚未重新访问原始学术数据库验证。对于这种规模的样本，不能宣称已形成完整研究趋势。

## 3. v1.9.1 已落实的代码修改

### 3.1 AI 检索词规划：新增功能

- 新增 `paper_radar/ai_planner.py`，可输入12—1500字符的自然语言研究目标。
- 复用已经配置的云端模型接口，但采用独立提示词，要求 JSON 格式输出主题、6—12个优先排序英文检索词、提示与排除概念。
- 对模型输出执行 JSON 解析、去重、英语短语格式检查和宽泛词过滤；无有效结果时明确失败。
- 新增 `POST /api/ai/plan` 和工作台折叠式检索词规划区域。
- **安全与交互边界**：用户主动触发才调用；发送范围为用户输入的研究描述；生成结果先预览并可修改；点击“应用至研究关键词”只填充输入框；用户再次点击主检索按钮后才会保存配置并运行。不会自动更改 Zotero 或执行文献抓取。
- 重要限制：arXiv 最多使用前12个关键词，OpenAlex、Crossref、Springer、Elsevier 现有适配器通常只使用前三个关键词。AI 已将核心词优先排序，并在界面提示；下一阶段仍需改造多查询检索执行器。

### 3.2 修复同 DOI 元数据覆盖：P0 数据一致性

原版在两个来源返回相同 DOI 时，晚到的短摘要可能覆盖已保存的完整长摘要，同时清空之前的中文速览。修订代码在 `paper_radar/core.py` 规范 DOI 前缀（例如 DOI URL、`doi:`），合并时保留长度更完整的摘要及已存的用户星标、阅读状态与下载状态。更丰富的摘要或题名发生变化时，旧 AI 分析会失效，避免正文与旧结论错配。

该策略以文本长度作为粗略完整度判断；若未来需要区分出版商正式版本与预印本，需要新增 `paper_versions` 和字段级来源优先级，而不能长期依赖长度判断。

### 3.3 模型分析版本控制与定量依据检查

- SQLite 迁移新增 `summary_fingerprint`、`summary_model`，不会删除原有文献记录。
- 指纹由论文题名、摘要、模型提供商、模型名称及提示词版本计算。证据或模型发生变化后，符合筛选条件的论文可重新进入 AI 队列。
- 新增模型结果校验：要求“研究问题、研究方法、关键结果、局限与待核查”四部分；检测部分明确百分比、倍数和时间数值，如果原始摘要没有对应字面依据则拒绝保存该次速览，回退原摘要。
- **限制**：该校验只覆盖一部分字面量数值，不能证明定性解释正确，也不能替代全文表格和实验设置核验。重分析旧摘要可能产生额外模型费用。

### 3.4 可靠性与文档

- `zotero_refresh_keywords` 对新用户默认关闭，避免每次检索覆盖手工编辑；已保存的旧配置项不会强制更改，建议升级后检查一次。
- 每个来源增加查询耗时记录，报告显示成功/失败、条数和耗时，便于排查慢源。
- 更新模型数据发送范围说明、README、CHANGELOG、HTTP API 使用指南与完整操作手册。
- 保留原有源码发包策略，排除个人 `data`、`downloads`、`reports`、`logs`、`.env` 和本地密钥。

## 5. 仍需解决的问题：按实施优先级排序

| 优先级 | 问题与影响 | 具体建设任务 | 建议验收指标 |
| --- | --- | --- | --- |
| P0 | 检索词多于3条时，多数来源只搜索前三条，可能漏掉相关论文 | 抽象 `QueryPlan`，按来源将每个主题拆成多条子查询；做去重、限速、上限与查询覆盖日志 | 记录每个查询命中量与失败原因；完整覆盖计划中的有效核心查询 |
| P0 | 单一设置与报告输出可能使不同课题互相覆盖 | 增加 `research_profiles`、`profile_id`、主题级输出目录和计划任务 | 两个主题交替运行时设置、历史报告和推荐数据互不覆盖 |
| P0 | 部分来源只提供题录、摘要贫乏，分析意义不足 | 增加摘要完整度字段与优先来源策略；二次元数据补齐 | 题录、摘要、全文三个证据级别明确显示 |
| P1 | 关键词召回覆盖有限，跨表达方式的论文容易遗漏 | 利用 OpenAlex `search.semantic` 做受控语义候选召回，与关键词精确检索合并 | 人工标注集上 Recall@50 优于 v1.9，且 Precision@10 不下降 |
| P1 | 仅有传统字符串匹配，排序难以体现阅读价值 | 可选本地 Embedding 或模型 API Embedding、混合排序与反馈 | 300篇人工标注文献评估 NDCG@10、Precision@10 |
| P1 | AI 摘要结构虽有约束，缺少可点击证据 | 结构化证据字段、页码/段落锚点，严格区分标题摘要与全文证据 | 每条量化结论可追溯至原文片段与对应条件 |
| P1 | 未覆盖顶会评审/接收状态 | 增加 OpenReview v2 公开论文适配器，旧会议兼容 v1，维护投稿/录用状态 | 投稿与最终接收记录区分；更新不重复入库 |
| P1 | 多来源规则与访问额限制不同 | 增加配额计量、429退避、来源状态历史和可恢复任务 | 单源失败不影响其他源；完整日志可诊断 |
| P2 | PDF 主要用于下载，尚未参与研究分析 | 对有合法访问权的 PDF 用结构解析器抽取章节、表格和页码 | 支持至少两种不同版式的基准论文与证据定位 |
| P2 | 报告缺少跨论文技术比较 | 方法/实验字段标准化、对比条件核验与主题周报 | 数值比较有实验条件与来源；样本不足时不生成趋势结论 |
| P2 | 文献库没有可追溯科研问答 | 建立混合检索 RAG，回答附论文 DOI 和页码位置 | 每个引文可以定位，找不到时拒绝编造 |
| P2 | Zotero 目前只读 | 基于 Zotero 10+ Local API 写入授权的笔记/标签，预览后提交，冲突检测 | 读写最小权限、逐项确认、具备历史撤销策略 |

### 一项需要及时关注的外部 API 变化

OpenAlex 当前官方资料说明，基础使用可以免密钥，规模化调用建议申请免费 API Key；语义搜索 `search.semantic` 最多利用2,000字符，最多返回50条，限速1请求/秒。不能把语义检索简单地与当前普通 `search` 参数同时放入一条请求。正式接入时应独立执行两类检索、合并去重并记录成本。

OpenReview 当前优先使用 API v2，较早会议可能需要旧 API；必须跟踪 venue 和实际公开状态。Zotero 10+ 的 Local API 已支持授权写入，需用户授权产生本地 API Key，并检查 `Zotero-Server-ID` 与版本前置条件。三者均应按官方文档适配，不能推断接口永远免费或对所有用户有相同授权。

- OpenAlex Semantic Search: https://help.openalex.org/api/semantic-search/
- OpenAlex Authentication: https://help.openalex.org/api/authentication/
- OpenReview API: https://docs.openreview.net/getting-started/using-the-api
- Zotero Local API: https://www.zotero.org/support/dev/web_api/v3/local_api

## 6. 下一轮实施顺序与范围界限

**第一阶段（v1.10）**：优先完成多研究主题管理、多查询检索覆盖、批次运行历史与源状态诊断。这三项是后续智能推荐可信运行的基础，且可离线测试；新增功能不应使基本检索需要模型 API。

**第二阶段（v1.11）**：OpenReview、语义召回、Embedding 与用户反馈，在人工标注的文献集合上与 v1.9 关键词排序比较。推荐原因应独立于模型自报的数字分数，并明确相关证据与待核查问题。

**第三阶段（v2.0）**：合法全文解析、表格/公式与证据抽取、论文比较、分主题周报和本地 RAG 问答；之后再考虑 Zotero 经授权回写。保持默认不上传私有全文、先展示成本和数据发送范围。

不建议在当前 1.9.1 立即引入多智能体自动执行网络操作、自主修改论文库或自动公开发布综述。模型规划结果需要人工确认，最终报告必须保留可追溯证据。

## 7. 升级和运行

1. 关闭正在运行的 Paper-Radar 和 Windows 后台计划任务；备份原文件夹中的 `settings.json`、`data/`、`downloads/`、`reports/`。
2. 将 v1.9.1 源码解压到**新的**程序目录，不要覆盖或删除旧版个人数据。确认新目录正常启动后，可迁移必要的配置及数据库。
3. 安装依赖（`python -m pip install -r requirements.txt`），运行 `python -m pytest -q` 与 `python -m compileall -q paper_radar main.py`，再启动 `python main.py --serve` 或使用 `start_windows.bat`。
4. 进入设置页检查模型 API、Zotero“每次检索前重新提取关键词”开关和文献来源，完成一次手动检索。使用 AI 规划前先保存并验证密钥。
5. 如需每日后台检索，确认新路径无误后重新安装 Windows 计划任务；核实不会同时启动旧目录中的任务。

**发布边界**：本次输出为源码修订及审阅，不包含或分发个人数据库、实际论文 PDF、私有 API Key 或付费数据库内容；不承诺真实机构授权源在未验收环境中可访问。升级前建议保留一次完整可回退备份。
