# Paper-Radar v1.12.0：实际代码实施、问题审阅和验收记录

日期：2026-11-04｜基线：v1.11.0 源码包｜性质：代码实改与回归验证

## 1. 主要结论

本轮已经把“全文阅读”第一阶段落实为可运行的本地 PDF 证据功能，同时新增研究者人工标注推荐质量评估工具。原有 v1.11.0 多主题、语义发现、AI 排序、Zotero、自动更新提醒和报告功能保留。此次重点提升可核验性、可复现性和旧数据兼容性，未引入复杂的多代理框架。

## 3. 实际修复的重要问题

1. 旧 PDF 在程序外被替换后，历史卡片虽会在状态页失效，但原先报告生成流程只对比数据库里的旧哈希。现已在 `load_report_cards` 重新核对**实际 PDF 文件的 SHA-256**，避免重新导出的 Word/Markdown 继续引用旧内容。
2. 全文状态接口查询不存在论文此前会由异常产生 HTTP 500，现改为 HTTP 404；这便于前端明确区分无此论文与服务器内部错误。
3. 对于在“全库”中查到但不属于当前主题的论文，原来的“当前论文”全文搜索仍隐含当前主题限制。现改为单篇搜索不附加主题关系，避免出现已显示索引却搜索不到的情况。
4. `paper_status`、`search_evidence` 在读 PDF 哈希出现文件系统错误时会安全地将内容视为过期，不会继续输出旧卡片。
5. 推荐评价原本只接受用户手写 CSV。现在可一键导出含题名、来源、链接、主题 ID 和排序的人工标注模板，并对可能被 Excel 执行的单元格进行基本防公式注入处理。

## 4. 测试结果与实际范围

最终运行：`PYTHONPATH=. python -m pytest -q`；Python 编译和 `node --check`；本地 `ThreadingHTTPServer` 真实路由测试；Chromium 的 `page.set_content` + **真实前端 JS/CSS 配合模拟后端**交互检查。测试覆盖 PDF 合成文件文本层、缓存重用、文件替换、错误路径、模型编造引文、无效数据、跨主题范围、Word/Markdown 引文及失效后重新导出、HTTP 返回码和 Token 校验。

## 5. 仍存在的限制和研发建议

- 论文 PDF 涉及双栏布局、矢量公式、图中结果、嵌入字体或扫描时，文本提取可能不完整；下一阶段应建设版面/表格级解析基准，并在有授权时选择 Docling 等结构化工具，不盲目增加模型 Token。
- 当前单篇 PDF 解析在后台线程中运行，虽然有大小、页数、片段上限，但尚无进程级 CPU/内存/时间隔离。后续应迁移到独立受限子进程并支持断点恢复。
- AI 引文核查证明原文字符串存在，无法自动证明中文解释、因果判断或实验结论完全成立。重要数据仍需研究者复核对应页码和上下文。
- 已有人工标注导出/计算工具，但**尚未收集真实标注集**，不能声称 v1.12 推荐 Precision@10 或召回率高于 v1.11。
- 尚未完成全文向量检索、引文关系图谱、跨论文统一实验对比和可追溯 RAG；建议 v1.13 优先研究结构化实验对照，v2.0 再考虑统一科研知识库。
- 系统仍需使用者在 Windows/macOS/Linux 实机确认启动脚本、云端模型凭据、出版社权限、真实 Zotero 与计划任务；GitHub 正式 Release 的创建由仓库发布者处理。

## 6. 合规与版本升级

仍只从官方/开放元数据源检索，PDF 下载遵守来源许可。全文索引会将原文片段保存在用户本地 SQLite 数据库；如用户拥有受限文件，应在使用云端模型前确认信息外发权限。源码包排除 `settings.json`、实际文献数据库、下载 PDF、运行日志、API Key。自动更新提醒继续仅指向本项目官方 GitHub Release，**不会替用户覆盖程序**。

正式对外发布前，应在真实电脑和模型账户中核验剩余条件，更新公众号实际操作截图，并将 `v1.12.0` 发布为公开正式 GitHub Release。
