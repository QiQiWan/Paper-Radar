# Paper-Radar v1.52.1 研究分析与文献库实机验收

## 操作入口

打开「研究分析」，输入研究问题，然后从「分析哪些论文」选择范围：

- **自动推荐相关论文（默认）**：系统检查当前主题所有题名和摘要，按相关性及研究维度覆盖推荐最多 16 篇。点击「查看与调整选文」后可搜索、添加或取消论文。推荐来源属于规则筛选，不代表专家标注或可靠的语义相关性评分。
- **当前主题全部论文**：当前主题中的全部论文进入分析，按每批最多 8 篇处理；无摘要论文仍计入主题覆盖，但没有可供提取的摘要证据。
- **手动选择论文**：点击「查看与调整选文」，按题名或论文编号搜索勾选。仅分析手动勾选的论文。一个任务最多 250 篇，全部主题模式最多 1,000 篇；超过上限必须拆分主题，程序不会静默截断。

点击「开始分析」后，页面立即显示分析任务和进度；完成后自动展示本次结果。每个结果保存当时的选文列表和摘要 SHA256 指纹，后续摘要变化会提示重新分析。高级区域保留模型发送授权、历史报告和 PDF 证据审核。

## 证据范围与模型授权

题名及摘要能支持描述“作者在摘要中报告了哪些方法、设置、结论和局限”。这些研究线索配有论文编号和原始摘要片段，尚未替代 PDF 全文核实；具体跨论文数值对照要求原始 PDF 引文、人工确认以及实验条件核查。

模型功能默认以本地基础分析为后备；**只有用户明确勾选本次允许发送题名、摘要片段和研究问题**并满足有效模型连接条件，才会发送到模型服务。全主题按每 8 篇构建一个独立批次，并记录总批次数、已提交数、成功数和失败数；单批失败不会停止其他批次。摘要原文线索会涵盖全部选中论文，模型失败时仍可查看离线结果。模型输出为待核对解释，不能自动确认数值。

当前本地预算模型只提供 token 数量与费用的**估算**，若提供商没有可信 usage 记录则实际账单成本为未知；不能用估算替代实际花费。

## 摘要补取状态

摘要「较完整」「较短」「缺失」「疑似截断」是数据质量分类；「当前可补」「已检查暂未改善」是操作状态，二者独立显示。对公开来源确实没有更长摘要的文献，系统会进入冷却期，避免重复检查。任务执行完但没有摘要改善时，明确记录 `no_changes`，页面更新每篇原因。摘要补取保留原有更完整内容，不以模型写作内容伪装为原始摘要。

## 研究分析任务恢复

任务状态保存在本地 SQLite 表 `inquiry_jobs_v152`，任务含独立运行编号、选文参数快照、进度、状态、分析结果及错误代码；服务重启后，旧进程的运行中任务标为「已中断」，可点击继续。完成的任务不可重复提交，用户重新分析会创建新的任务。实验结果/报告采用同任务编号写入，防止失败恢复时重复生成。

任务生成后可在结果页与日志导出里核对选文数、使用的摘要数、分批进度、模型是否参与及运行耗时。只有实际执行且成功的模型请求才能标记为成功，状态「报告已保存」不足以证明模型成功调用。

## v1.52.1 真实文献库验收

**当前提供的代码包未包括用户本机的 72 篇论文数据库。** 附件的空库验收仅证明测量工具在缺乏真实数据时不编造数字。请在正在使用的工作站运行以下命令，以生成可上传的真实指标 ZIP：

```bash
python -m paper_radar.research_acceptance \
  --db "/path/to/your/papers.sqlite3" \
  --topic default --expected-count 72 \
  --mode all --output "Paper-Radar-Pilot-v1521.zip"
```

Windows PowerShell 可以把上述命令写成一行，改用实际 SQLite 路径。首次只检查数据、无需分析可添加 `--no-analysis`。工作站的数据库目录可在设置页的数据与备份中核对。**运行前备份数据库**，因为分析会保存研究报告快照。

解压生成的试点 ZIP：`summary.json` 包含样本数、摘要分类、全部选文数、分批数、真实 PDF 率、人工字段准确率、人工审核耗时、有效对照组数、耗时和模型状态；`paper_coverage.csv` 含本次论文与推荐覆盖情况；`README_FIRST.md` 解释缺测字段。

缺少下载审核记录的 PDF 获取率为 `null`；未做独立人工标注的字段准确率为 `null`；尚未计时的人工审核时长也为 `null`。请不要把这几个字段为空解释成零水平。推荐准确率与关键论文召回率依赖人工金标准，可自行提供 `--gold-relevance-csv`，至少包含列 `paper_id,relevant`（1/0）。

## 真实72篇验收检查点

| 检查点 | 验证方法 | 应记录的结果 |
| --- | --- | --- |
| 摘要覆盖 | 直接查询正在使用的数据目录 | 有效、过短、缺失、可能截断、已检查暂未改善、当前可补 |
| 默认推荐 | 人工标注相关性，在同一主题下运行推荐 | 推荐论文清单、精准率、关键论文召回率（需标注） |
| 全部主题 | 选择「当前主题全部论文」并提交 | 选中数 = 主题数（预计72），9批，每批≤8，无静默遗漏 |
| 手动选择 | 按论文编号添加、取消论文各一次 | 本次选文与结果来源集合相同 |
| 研究分析质量 | 阅读报告中的摘要原文片段 | 摘要引用匹配率、人工核查有效性（两项分开记录） |
| 失败恢复 | 人为中断测试实例后重启 | 标记中断，可继续；不重复生成同一报告 |
| 模型调用与费用 | 明确授权后使用可访问模型运行 | 各批状态、失败比例、时间、费用估算、实际用量缺测理由 |
| PDF 及人工审核 | 在高级 PDF 审核流程完成后导出 | 真正下载成功率、逐字段正确率、每条审核耗时、可比组数 |

## 已知限制

1. v1.52.1 只完成本地版三模式界面；公网版保留既有研究范围和权限逻辑。后续可按相同规范引入多租户作用域选择。
2. 启用模型后的实际回答质量、调用费用及 72 篇真实论文样本的文献覆盖率，需要用户工作站数据和模型账单才能测量。
3. 全主题模式不漏掉论文的题名/摘要读取；模型无法解释空摘要内容。全文实验数值结论仍需原文和人工核实。
4. 首次运行的数据库、模型服务及启动器需在 Windows/macOS/Linux 实机复验。
