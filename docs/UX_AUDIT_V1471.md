# Paper-Radar v1.47.1 交互与可靠性迭代审阅

日期：2026 年 11 月 10 日  
基线：用户提供的 v1.46.0 → 已完成的 v1.47.0 工作流改版 → 本次 v1.47.1。  
交付性质：完整源码的研发验证版本。尚未通过真实用户可用性试验或跨平台安装验收。

## 一、总体判断

v1.47.0 已完成主导航重组、首页新手清单、研究问题合并和普通功能与高级功能分层。v1.47.1 进一步处理实际使用中容易造成误解、任务重复及数据结果不可读的问题。重点是：检索到入库的数据链路、PDF 的真实访问、任务恢复、报告的明确产出，以及“题录”和“已经核对的实验依据”的区别。

## 三、验证方法与结果

### 3.1 浏览器实际操作（隔离测试数据）

Chromium 加载仓库现有 HTML/CSS/JavaScript，用户操作由真实浏览器事件触发；HTTP 请求通过测试桥接进入实际 Python 本地／公网 HTTP 处理器，最终读写隔离 SQLite。运行时使用临时 `PAPER_RADAR_USER_HOME`、一次性测试账号、人工生成的论文题录和原创测试 PDF，不访问个人数据、云模型或真实学术服务。

12/12 条操作路径通过，覆盖：本地首次加载与断线重连、收藏持久化、本地／公网证据不足提示；公网账号与文献库查询、关键词输入校验、离线来源任务执行及持久化、PDF 上传与哈希校验及字节区间读取、浏览器阅读面板、后台报告生成并在页面阅读、任务状态连接失败后的安全恢复。浏览器页面 JavaScript 异常数为 0。

**限制：**当前托管 Chromium 环境阻止打开本机 HTTP 地址。测试通过 `set_content()` 加载真实前端，用受控桥接调用真正的本地 HTTP 服务；无法据此认定浏览器原生地址导航、Cookie 写入、PDF iframe 的完整渲染、下载对话框及真实外部网络已经验收。PDF 只验证了上传、摘要、全量读取、Range 206、阅读面板挂载和 iframe 地址构造。当前结果亦不能替代独立的真人用户可用性试验。

### 3.2 静态布局与代码回归

桌面 1440px / 手机 390px，两套工作台各 5 个常用页面，共 20/20 项布局检查通过，检测到的水平溢出为 0。新版 JavaScript 与 Python 语法检查通过。扩展 pytest 覆盖原有的任务恢复、PDF、报告、安全、研究分析、UI 等测试；全仓库共发现 850 个测试项。一次连续全量执行在 125 秒运行时限内推进至约 59%，无记录到失败；为规避耗时测试引起的超时，随后按收集顺序拆分执行 0–499 与 500–849 号测试，分别 **500 项通过（117.98 秒）** 和 **350 项通过（51.59 秒）**，完整覆盖全部 850 项。最后针对报告渲染修订执行 28 项聚焦测试及 12 项浏览器链路，全部通过。分块通过不等同于同一进程连续执行 850 项通过。

### 3.3 发现并关闭的问题

- 初版隔离测试以 50ms 频率重复读工作区 SQLite，与后台线程竞争资源，检索任务迟迟无法结束。调整为先等待真实任务完成，再验证持久化；在真实 HTTP 流程下检索成功且论文入库。没有对生产检索算法做无证据修改。
- 公网报告生成最初只显示通用“任务完成”，已区分报告生成成功及相关计数，并加入回归测试。
- 只有题录、尚无人工核对证据时，旧报告呈现 0 篇论文。现将题录清单与可核对证据分开呈现，仍禁止未经验证的跨论文数值比较。
- 本地断线、新任务提交、PDF 未解析和错误代码方面的提示均已收敛。

## 四、建议的用户验收任务

请使用非开发人员在独立测试账户中完成以下任务，不提供技术流程说明，仅提供“快速开始”用户手册：

1. 新建研究主题，填写英文检索词并运行一次检索。
2. 从文献库选择一篇论文，收藏、阅读摘要、保存笔记。
3. 上传或使用已授权的 PDF，打开原文，并查看其是否完成全文读取。
4. 输入研究问题，面对证据不足时判断下一步操作。
5. 生成报告，区分已收录题录、已有 PDF 和已核对的实验依据。
6. 模拟服务断线，确认不会重复发起有成本的任务。

建议至少 5 名未参与开发的科研用户独立完成。记录任务成功率、时长、误操作次数、求助次数、术语理解问题；此前提出的“完成一次检索不超过 5 分钟”等仍是目标，暂时不能作为实测数据。

## 五、如何运行

- Windows：解压到独立目录后运行 `start_windows.bat`。
- macOS/Linux：解压后按根目录 `README.md` 的说明运行 `./start_macos_linux.sh`。
- 更新前备份旧版用户数据，避免将开发测试数据与正式数据目录混合。
- 聚焦代码测试：`python -m pytest -q tests/test_v1471_recovery_and_evidence.py tests/test_v147_user_experience.py`。
- 浏览器隔离链路：`python -m tools.qa_v1471_journeys --out-dir <输出目录> --browser-path <本机 Chromium 或 Chrome 路径>`；必须为命令设置一个新的 `PAPER_RADAR_USER_HOME` 绝对路径。测试会新建账号、数据库和 PDF，勿与正式数据目录共用。
- 静态页面审阅：设置 `PAPER_RADAR_QA_OUTPUT` 后运行 `python tools/qa_v147_layout.py`。
