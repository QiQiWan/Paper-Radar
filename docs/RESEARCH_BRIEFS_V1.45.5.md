# v1.45.5 持续跟进可靠性：操作与验收

## 适用范围

本版本对本地研究库与公网用户独立工作区的周期性科研简报增加**持久化任务检查点、事件消费账本、重复执行幂等控制和历史简报更正**。本地数据库从迁移版本 8 增加到 9，公网工作区从版本 15 增加到 16；旧迁移校验和不变，不删除历史数据。

## 为什么修复

此前依赖事件 ID 单向游标，并额外用事件 `observed_at` 与周期终点比较。如果论文事件在报告完成后才被抓取，或其原始观测时间落在更早周期，即使入库也可能被游标跳过。重复执行也容易把再次发现的事件误计为新进展。

## 实际处理流程

1. 用户通过现有研究跟进页面设置日/周/月简报。任务启动时将当前最大事件 ID 固定为此次扫描的 `watermark_id`。
2. 事件按有界批次入库 `research_brief_job_events`；每批与 `last_scanned_id` 同事务持久化。进程中断可从该位置恢复。
3. 周期简报生成后，事件 ID 写入 `research_brief_event_ledger`，消费键由 `topic_id + cadence + event_id` 唯一确定。
4. 旧周期之后到达的新事件若已存在对应周期简报，只产生追加的 `research_brief_amendments`，不覆盖已发布快照。
5. 已确认结论发生修订时记录 `new / revised / no_longer_current` 差异，原报告保留不变，供用户审计。

**注意：**事件去重是按同一主题和周期频率分别处理，日简报与周简报可以同时引用同一篇论文；用户不能把“已检索到”理解为“模型已经确认其科学结论”。

## 恢复与验收

- 在导入了 510 条连续事件的测试中，首次仅运行一批 75 条并模拟进程退出，新连接继续运行到 510 条后，最终生成一份简报，事件账本 510 条。
- 同一批次连续重跑，历史简报 ID 不变且事件不重复计数。
- 新插入带较旧观测时间的事件，可追加到对应历史周期的更正记录。
- 各主题和各简报周期分开登记事件消费账本。

科研简报更正仅作为追加信息，不会回写原始报告。真实长周期、多用户高并发仍需要在正式工作站持续验收。


### 批次运行安全性

扫描任务每批重新延长租约（120 秒），防止大规模批处理只使用启动时的租约期限。跨进程重复运行以数据库内游标和事件消费账本为准。
