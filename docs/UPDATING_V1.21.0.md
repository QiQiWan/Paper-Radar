# Paper-Radar v1.20.0 → v1.21.0 升级指南

**版本**：1.21.0，2026-11-05。本次未更改桌面/公网数据库结构，无新迁移步骤。

1. **停止程序**：Windows 先关闭 Paper-Radar 本地工作台及计划任务；公网先停止 Web 与所有独立 Worker，避免服务运行中替换代码。
2. **备份整个旧目录**。务必保留 `settings.json`、`data/`、`downloads/`、`reports/`、`logs/`，公网保留 `PAPERRADAR_PORTAL_DATA` 所指的数据根目录及账户数据库 `accounts.sqlite3`、所有 `users/` 目录和 PDF。
3. **解压 `Paper-Radar_v1.21.0_Source.zip`** 到独立目录，再将程序代码、前端静态文件、测试、脚本及文档同步到现有安装目录。不要用源码压缩包的空目录覆盖个人数据库或密钥。
4. 检查 `paper_radar/sources/supervisor.py`、`paper_radar/sources/source_process.py`、`paper_radar/static/portal.js` 等文件存在；按旧版方式运行启动脚本，并确认工作台显示 **1.21.0**。
5. **验证断网检索**：在本地设置页展开“来源故障与超时控制”，默认单组 10 秒、一次来源发现总共 75 秒。用可安全控制的测试网络断开场景检查任务是否失败收敛。正常网络中至少一个来源成功时，应继续入库，失败来源在诊断面板显示。
6. **验证 PDF**：选择当前账号有访问权限的 PDF，进入论文库“查看证据”，检查左右两栏和原文页码。无 PDF 时先上传或获取开放版本。浏览器内嵌 PDF 不工作时使用“单独标签打开 PDF”。
7. **验证报告**：在“研究报告”打开一份有结构化证据的历史快照，检查实验对比矩阵、筛选、基线冲突提示、原文跳转；没有足够证据时允许矩阵显示“无候选组”。
8. **验证安全和服务**：公网账号 A 不能读取账号 B 的 PDF；独立 Worker、任务队列、历史报告与自动更新保留旧流程。

**回滚：** 如果需要回退到 v1.20.0，停止所有服务并恢复旧版代码；虽然本次没有数据库迁移，仍建议恢复升级前的完整备份以避免覆盖升级期间新增的研究成果。生产版自动更新只有使用原有受信任 Ed25519 私钥签署并发布正式 GitHub Release 后才能让旧客户端可信自动安装。

本次没有 Windows/生产服务器实际验收，须在目标设备执行。若目标环境需要校园网、机构 VPN、授权 API Key，正确配置后再尝试对应的论文来源。
