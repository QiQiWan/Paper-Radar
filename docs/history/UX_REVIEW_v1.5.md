# Paper-Radar v1.5：代码、界面与交互审阅

版本：1.5.0｜日期：2026-11-03

## 一、总体判断

v1.4 已具备本地检索、Zotero 收藏夹分析、PDF 下载和 Word 报告等基础能力。主要问题集中在信息规模扩大后缺少分页、下载失败缺少直接处理入口、首页频繁查询影响响应速度、部分操作状态容易误解，以及移动端导航占用过多宽度。

本轮保持“本地浏览器工作台 + Python 核心模块 + SQLite”的方案，优先修正现有使用路径。没有增加复杂的数据分析模型或第三方前端框架。

## 三、保留的技术边界

- 当前文献来源为 arXiv 与 OpenAlex，尚未加入 OpenReview、PubMed 和出版社专有数据库。
- Zotero 关键词提取采用本地文本方法，尚未引入 Embedding 或专用语义检索模型。中文题录较多时需要人工检查关键词。
- 下载仅处理明确可公开获取的 PDF 地址，不绕过付费墙，不保证所有链接可用。
- Windows 使用系统计划任务，其他操作系统尚无图形化后台任务管理入口。
- Word 的优先阅读依据配置关键词的相关度，不能代替同行评审或论文质量评价。

## 四、验证结果

- Python：45项自动化测试通过，包括旧数据库迁移、Zotero 模拟读库、PDF 下载、分页与全量导出等。
- JavaScript：`node --check paper_radar/static/app.js` 通过。
- 页面：以实际 HTML/CSS/JS 和模拟接口数据完成交互检查，验证40→80篇加载、下载失败重试入口、深色模式、390px移动端导航；未出现 JavaScript 异常和页面横向溢出。
- 服务接口：用本地 HTTP 服务与测试数据库验证分页、下载状态筛选和 Host 校验。
- Word：最终稿须经渲染逐页检查后发布。

由于当前执行环境限制浏览器直接连接本地服务，浏览器端采取模拟接口数据。实际 Windows 计划任务、真实 Zotero 版本兼容、真实云端 API 和下载网站访问仍需在用户电脑验收。

## 五、下一阶段优化建议

| 优先级 | 项目 | 理由与验收方向 |
| --- | --- | --- |
| P1 | 多研究主题管理 | 用户可分别保存“神经算子”“热管理”等独立任务；报告按主题归档，避免覆盖 |
| P1 | 检索任务与来源执行历史 | 记录每次运行的开始/结束时间、各来源成功数量和失败原因，便于追踪缺失 |
| P1 | Zotero 接口兼容性 | 使用不同 Zotero 版本的真实数据库与 Local API 验证，补充自动检测与错误提示 |
| P2 | PDF 下载队列 | 失败自动退避重试、批次进度、暂停与恢复，避免批量操作重复提交 |
| P2 | OpenReview 来源 | 通过官方 API 获取公开投稿、会议及状态；区分投稿与最终接收论文 |
| P2 | 研究兴趣语义匹配 | 可选嵌入模型与关键词混合排序，记录匹配依据并评估误召回 |
| P3 | 学术全文解析 | 对合法获取的 PDF 提取方法、实验与局限性，用于主题比较及周报 |

## 六、GitHub 发布检查
