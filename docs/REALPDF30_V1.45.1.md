# v1.45.1 | 长篇 PDF 索引与真实论文评估

适用范围：Paper-Radar v1.45.1 研发验证版。本版基于已实现的 v1.44.0 科研综合与 v1.45.0 持续研究能力，聚焦可复现实验评估。

## 已完成变更

1. **长篇 PDF 索引**：本地索引上限由 100 页提高到 240 页、片段数上限由 600 提高到 1800；升级解析器版本，旧版不完整索引在下次解析时会重新建立。公网页面解析 Worker 由 120 页上限提高至 240 页，并保留子进程、资源上限和调用超时。
2. **30 篇真实 PDF 评估集**：元数据、30 个冻结版本及 SHA-256、117 条实验候选、139 道研究问答题、34 组方法及冲突配对、16/7/7 论文级划分。源 PDF 由用户从 arXiv 下载并保存在本地，程序检查 SHA；不向仓库提交原论文 PDF。
3. **端到端离线检查**：使用单独创建的 SQLite 临时数据库，顺序运行全文索引。每篇论文在隔离子进程中执行，失败保留错误、继续其他论文，重复运行使用已完成索引缓存。
4. **质量诊断**：分别报告“候选页是否已索引”“原文摘录是否在 pypdf 文本中保持连续”“候选关键词检索 Top20 是否命中候选页”，并输出每条候选证据诊断。三项都只是程序检查，不代表模型科研正确率。
5. **人工审核与严格金标准**：保留双人独立标注、论文级防泄漏划分和冲突仲裁流程。人工未全部审定、金标准关键字段缺失、PDF 版本哈希不一致或引文无法在 PDF 指定页定位时，正式指标维持未测量。

## 一键执行

Windows：进入项目根目录，双击 `start_windows.bat --eval`。程序首先检查 PDF 是否可用，缺失时从 arXiv 版本化地址下载。Linux/macOS：运行 `bash ./start_macos_linux.sh --eval`。使用**已有 Python 环境**，无需新建虚拟环境、Node 或 npm。项目依赖以根目录 `requirements.txt` 为准；下载需要网络。

手动操作（支持自定义保存路径）：

```bash
python benchmarks/real_pdf30/scripts/download_official_pdfs.py --manifest benchmarks/real_pdf30/manifest.json --dest benchmarks/real_pdf30/pdfs
python -m tools.triage_realpdf30 --dataset benchmarks/real_pdf30 --output realpdf30_triage_v1451
python -m tools.eval_realpdf30 --dataset benchmarks/real_pdf30 --output realpdf30_eval_v1451 --timeout 100
python benchmarks/real_pdf30/scripts/validate_and_score.py --dataset benchmarks/real_pdf30
```

若原始 PDF 已放在其他位置，可以附加 `--pdf-dir /your/private/pdf/folder`，不需要复制到源码目录。评估输出和用户正式数据库独立；只会写入 `realpdf30_eval_v1451` 和 `realpdf30_triage_v1451`。所有 PDF 只读使用并验证固定版本哈希，不会调用外部模型。

生成文件包括：`result.json`（原始指标与失败分类）、`result.md`（人可读报告）、`candidate_triage.csv`（预标注风险）、`review_queue.csv`（每篇优先一条的人工审核队列）、`triage_summary.json`（噪声分布）。

## 重要质量界限

- 原评估集的 117 条记录由规则抽取，部分数字来自文献引用编号、章节标题或表格序号。43 条标为优先复核也仍然未获人工确认。禁止把规则优先级当成模型置信度或“已确认实验数值”。
- 由于 pypdf、PyMuPDF 在双栏/表格上的文本排序不同，引文是否逐字连续仅作为全文解析诊断。准确识别实验表格需要进一步补齐行列几何关系、数据集、方法和实验配置审核。
- 139 道研究任务为审核候选；没有真实模型调用结果与双人审核前，不输出问答正确率或冲突检测准确率。
- 提高页数上限增加了对长篇 PDF 的 CPU / 内存开销；公网部署应继续保留每用户配额、独立 Worker 和超时控制。
