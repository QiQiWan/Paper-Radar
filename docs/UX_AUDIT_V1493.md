# Paper-Radar v1.49.3：研究分析、阅读卡片与日志系统审阅

## 一、结论

v1.49.2 的研究分析入口能保存研究简报，但当 PDF 原文锚点与人工确认结论为零时，只能输出宽泛的题录清单、风险提示和下一步建议，无法回答跨论文实验的共同结果。该状态容易让用户误以为模型已经完成综合分析。v1.49.3 将结果严格分层，并进一步提高题录筛选精度，同时为每次任务建立可导出的阶段诊断。

根据用户上传的 2026-11-10 诊断与研究简报：60 篇收录、48 篇旧式题录匹配、缺 3 篇摘要、0 条原文锚点、0 条人工确认结论、3 个来源未完成检索。两次 `/api/inquiry/run` 返回 201 只代表报告生成/保存成功，不能推断云模型已经参与。原始日志也未记录模型调用是否执行、论文在各阶段减少的具体原因。

## 三、研究结果如何解读

新页面分为三部分。首先是从题名、摘要得到的**相关论文和研究主题线索**，这些可以指导阅读，但对实验结果只具有检索线索意义。其次是**已人工核对 PDF 原文的研究结论**，必须带有效 PDF 引用；当数量为零时，页面直接说明还未完成这个阶段。最后是模型可选提供的**待核实阅读问题**，仅引用输入中已有论文编号，不能填入模型杜撰的实验数字。

算法仍使用显式科研词组，覆盖不等于英文科学语义理解。排在前面的论文不必然在研究质量上更强。现有题录与摘要不包含完整数据集、模型设置、统计显著性和计算开销，暂时无法得到可靠的跨论文实验共识。

## 四、日志如何排查

在设置 → 运行记录的“研究分析阶段记录”中，找到匿名运行编号；下载运行日志 ZIP 后先阅读 `README_FIRST.md`，再看 `research_runs.json` 中的五个阶段、模型状态以及 `outcome_code`。`MODEL_DISABLED` 表示本次未要求调用模型；`MODEL_SKIPPED` 表示没有可执行的模型任务；`MODEL_USED` 表示模型阶段返回了有效输出；`MODEL_RESPONSE_INVALID` 等意味着模型结果无效，程序退回本地阅读建议；`CANDIDATE_ONLY` 表示只有题录层面的结果；`CITED_EVIDENCE` 表示本次关联了经核对的 PDF 结论。

运行日志默认只存储阶段、结果码、耗时、数量和有限的代码定位信息。为了避免泄露科研问题和 PDF 内容，默认不会保存完整 Prompt、API Key 或原文。可选的历史任务自由文本日志仍需在分享前人工检查。最近采样窗口最多 500 条，不能拿它当整段运行历史的全量统计。

## 五、仍需推进的科学能力

1. 对高相关论文安排有资源预算的 PDF 下载、全文解析、段落/表格/公式定位和候选证据抽取，给用户审批后保存可验证的证据记录；明确失败可续跑和来源许可限制。
2. 针对“跨网格/跨几何”问题定义统一实验对比字段：训练几何、测试几何、训练网格、测试网格、误差指标、分布内外划分、基线、样本预算和重复试验。没有这些字段不做横向数值结论。
3. 使用固定真实论文集与两位独立标注者评估题录筛选准确率、证据定位率和模型研究问答质量；目前没有正式验证过这些指标。
4. 在实际 Mac/Windows 电脑上接入真实模型密钥进行经用户许可的联网测试；本轮模拟了失败/非法输出路径，未执行真实计费模型调用。
