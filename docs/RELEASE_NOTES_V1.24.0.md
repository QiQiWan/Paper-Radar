# Paper-Radar v1.24.0 — 可追溯的实验关系复核与跨论文比较

本版本在 v1.23.0 的 PDF 证据和可选表格候选基础上，新增人工证据复核、条件字段登记、跨论文配对审核和不可变的复核历史。系统保留原 PDF 引文校验结果，不把字段同名、字符串匹配或用户标记当作自动验证的统计结论。

## 功能实现

1. **两级审核：** 每条已经与当前 PDF 指纹/引文匹配的证据新增“待复核 / 人工核对通过 / 排除”状态；核对通过须登记数据集版本、测试划分、指标单位和方向、聚合方法、训练预算、评估协议，以及明确的人工判断依据。审核人、时间、当前 PDF SHA、完整条件及历次变更存入账户独立数据库。无 PDF 的 CSV 导入证据不能借此直接提升为已核验实验关系。
2. **配对判定：** 可逐条登记两篇论文之间的“人工确认可比 / 不可比 / 待复核”。只有两条各自审核通过、指标和基线等字段一致、完整条件一致、源 PDF 仍有效时，允许确认一对证据可比；人工明确否决的配对记录为不可比。**配对审核只是人的实验条件审核记录，不证明复现、统计显著性或性能排名。**
3. **失效控制：** 替换 PDF 后旧审核立即不参与报告，活跃复核和相关配对登记清除；PDF hash、模型抽取引文、条件人工更正亦会造成比较审核失效。所有变更保留在只读的历史审核表内，供来源追踪。主题及账户访问控制沿用原有认证/CSRF 流程；配对确认在 SQLite 写事务中再次校验当前审核条件，避免并发更正后的过时确认。
4. **研究报告：** 报告对每条证据显示用户复核状态，对每个跨论文候选组显示人工确认的配对数量、条件不符的配对数量及复核要求；拒绝证据不再作为报告证据。永远不自动生成声称某篇论文相对另一篇论文的性能百分比提升；历史报告保持不可变，修改人工复核后要重新生成报告。
5. **交互：** PDF 证据面板采用默认折叠的复核表单，跨论文比较矩阵显示配对复核表单，均使用安全 DOM `textContent`。新增 `/api/public/evidence/review`、`/api/public/comparisons/review`、`/api/public/reviews/history`。
6. **评估：** `python -m tools.eval_comparison_policy --out result.json` 使用附带的 15 个**人工构造**的规则正反例验证误放行/错拦截行为，与真实论文模型评测明确分离。原 3 篇真实论文、6 条人工证据、5 条负例基准仍保留；需取得原 PDF 及独立人工标注后才能测量真正的学术准确率和正例召回率。

## 科研边界与实现限制

- “人工核对通过”“用户确认可比”是**用户输入的审核事实**，不代表软件利用版面坐标或第三方专家完成自动关系验证。布局候选仍需对照 PDF 表格行列与原始实验方法。
- 配对规则要求字段和人工声明完全一致，对合理但不同单位的结果不做换算（如 0.91 与 91%）。同一值对应不同数据划分或训练预算会被拒绝直接比较。
- 多用户数据使用独立 workspace，生产环境需要额外执行账号并发、数据库权限、备份恢复及访问日志审查。
- 合成规则集的 100% 准确率仅代表此 15 个人工构造条件，不能引用为真实实验抽取 F1、跨论文可信率或算法泛化能力。
- 可选 PyMuPDF/本地 OCR 的第三方许可证、安装、精度与吞吐仍遵循 v1.23.0 说明。
