# Paper-Radar v1.19.1 功能、UI 与交互优化审阅

版本：1.19.1；审阅日期：2026-11-05；基线：v1.19.0 及此前功能/UX 审查。

## 1. 总体判断

本轮优先修复会影响日常任务完成的 P0 问题：看不清科研任务执行阶段、失败后无法复盘、报告需要重新计算、旧报告不便阅读，以及部分表单缺少可访问标签与低对比度文字。原有多账号、独立 Worker、PDF、科研 Agent、Zotero、Word/Markdown 和启动更新链保持。

**本轮交付的是现有单页公网上的质量修复。** 公网多页面架构、跨论文可比性图谱、PDF 左右双栏阅读、邮箱验证仍需后续版本实现。任何设计效果评级均是启发式审阅，不代表终端科研人员实测满意度。

## 3. 新的任务和报告生命周期

```text
账号提交任务
  -> SQLite 事务保存任务
  -> Worker 领取任务并获得租约令牌
  -> 写入 starting / discovery / download / fulltext / evidence / synthesis 阶段事件
  -> 运行报告 Agent 并写入本账号的 research_reports 快照
  -> 写入完成/失败/取消事件
  -> Web 只读查看任务与历史报告；不重新发起模型分析
```

任务阶段事件包含有界的状态、时间和计数；不会存入 API Key、完整 PDF 原文或模型提示词。阶段更新沿用 v1.19.0 的租约校验；过期持有者不能覆盖后续结果。完整状态机制仍依赖 SQLite 持久化和独立 Worker。

报告快照字段包括报告 ID、账号所在工作区、主题、关联任务、生成时间、schema_version、摘要 SHA-256、论文数、实验证据数、结构化摘要和 Markdown 文本。每个主题最多保留最近 40 份，单份 Markdown/摘要上限分别约 300 KB。归档是当时的分析结果：后续证据变化不会静默改写历史。**科研引用仍须检查报告所列的原始 PDF 版本与人工核验情况。**

## 4. 安全与数据边界

1. `GET /api/public/jobs/detail?id=` 验证登录身份并按 `account_id` 过滤；跨账号任务返回不存在。
2. `GET /api/public/reports?topic_id=` 和 `GET /api/public/reports/view?id=` 只查阅当前账号工作区。报告 ID 为 32 位小写十六进制标识。
3. 在线报告文本通过 `textContent` 等 DOM API 构建，不直接执行 Markdown 中的 HTML/JavaScript；对于长表格采用区域滚动。
4. 研究报告不包含可由公网客户端直接访问的本机路径与系统凭据；旧桌面管理 API 保持不对公网开放。
5. 升级新增数据库迁移账号库 v5→v6、工作区 v2→v3。生产环境先停机，再备份完整数据目录。

## 5. 实际 UI 复核和定量结果

使用真实 `portal.html`/`portal.css`/`portal.js`，配合模拟 HTTP 数据在 Chromium 检查，单独通过真实本地 HTTP 服务器测试验证账号隔离与报告读取。模拟数据用于校验控件和布局，不能代表生产数据库的所有异常内容。

| 项目 | 审阅结果 |
|---|---|
| 静态输入控件访问标签 | 新版公网默认页面缺失 0 项（程序化检测）；桌面此前缺失 4 处已补充 |
| 辅助文字颜色 | 公网主要辅助文字改为 `#42586b`、桌面浅色辅助色 `#4b6077`，相对白底对比度符合 4.5:1 的测试约束 |

**审阅意见：** 任务执行和研究报告的可发现性有所提升，针对明确的 P0 问题已形成可测试的闭环。但新功能增加了单页内容总长度。默认展开前手机页面仍超过 3000px，长期体验优化的核心应是独立的“任务中心”和“研究报告”页面。下一阶段建议优先将这两部分搬离主工作台，参考之前 v1.20 交互原型。

## 6. 研发验收结果与未覆盖范围

- **回归测试：** 327/327，通过（311 旧版及 16 新增专项）。
- **真实 HTTP 测试：** 验证报告列表、只读读取、用户 A 无权访问用户 B 数据、无会话拒绝读取、任务详情及旧桌面端 API 隔离。
- **独立 Worker：** 单独子进程执行研究综合任务，成功生成报告快照并写入关联任务状态。
- **前端模拟浏览器：** Chromium 显示实际页面代码、模拟 API，观察表格、任务、历史报告及危险 HTML 字符串，页面脚本无异常；不是公网 HTTPS 服务器的端到端验收。
- **待实机：** 真实 Nginx/HTTPS、Windows 自动更新、辅助技术读屏器、长时间并发、高负载复杂论文和真实终端用户完成率。

## 7. 后续 v1.20 迭代顺序

- P0-A：公网工作台五入口导航（工作台/论文库/任务中心/研究报告/我的），保留主题选择和滚动位置。
- P0-B：任务中心可查筛选、失败恢复操作、分阶段输入/输出数量、下载/模型费用提示与统一错误码。
- P1-A：文献库搜索、相关性反馈、星标与阅读状态，在公网与桌面之间共享设计语言。
- P1-B：报告中心独立阅读视图、原文证据锚点、移动端表格卡片化；与 SynthesisAgent 比较矩阵统一。
- P1-C：PDF 双栏阅读与实验结构化比较，严格区分人工核验、模型提示与用户未核验导入。
- P2：前端拆分为业务组件、统一可访问性色板/字体、真实科研用户操作测试。

## 8. 结论

v1.19.1 的新增工作已经超出简单视觉修补：任务过程、报告结果与阅读操作形成持久数据链，具备独立测试和账号安全边界。下一轮最有价值的是 v1.20 多页面导航与任务/报告中心，而非继续向单页追加模块。
