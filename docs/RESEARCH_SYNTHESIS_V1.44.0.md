# v1.44.0 科研综合智能体：实现与验收

适用范围：Paper-Radar v1.45.0 集成验证版；本模块的功能里程碑为 v1.44.0。

## 一、功能范围与处理原则

综合研究从一个具体科学问题开始。程序读取当前主题下已经由研究人员确认的 PDF 结论和证据锚点，计算主题相关性，组织跨论文方法证据、实验差异候选与待验证问题，保存一份可回查的综合报告。新建报告与历史报告的读取都保留源文献的页码和 PDF 指纹。

PDF 已索引、但未产生人工确认结论时，工作台仍会按问题搜索全文片段。此类材料单独列在“待核实的 PDF 原文片段”，不进入已确认结论，也不会自动变成研究发现。

大模型是按需增强项。本地版通过用户主动勾选“模型解释”及“本次传输授权”后，才向已配置的服务商发送问题、人工确认结论和部分短引用。模型返回严格限制在已存在的结论 ID 范围内；其新解释、研究建议均标记为待人工复核。公网版当前仅提供本地确定性综合，未开放云端模型调用。

## 二、数据流和实现

```text
研究问题
  ↓
当前主题 EvidenceChain 读取与 PDF/修订状态复核
  ├─ 有效人工确认结论 → 关键词相关性排名 → 结论与原文锚点
  └─ 当前索引 PDF → 全文片段候选（仅本地版；每次最多 18 条）
  ↓
方法名称候选 → 方法-论文-结论对照表
  ↓
同字段实验值差异候选 + 相反表述线索（两者均不自动判定冲突）
  ↓
可选 LLM 整理：限制可引用 claim ID，解释单独标记待核验
  ↓
不可修改的 SQLite 历史报告 + Markdown 导出
  ↓
重新打开时重新核查来源 PDF 与人工结论是否变化
```

代码：`paper_radar/research_synthesis_agent.py`。现有 `evidence_chain.py` 是确认结论和当前源证据的唯一事实来源；`fulltext.search_evidence` 只提供原文候选。方法类别通过显式方法名匹配获得，不能当作结构化方法理解。实验差异仅处理已有人工复核的记录字段；不同数值不直接说明两个论文结论矛盾。

存储表：`research_synthesis_snapshots`，字段包含 ID、主题、问题、生成时间、报告 SHA256 和报告 JSON，禁止 UPDATE/DELETE。原始报告保存后不更改；再次阅读时若 PDF、锚点或人工修订发生变化，界面显示 `needs_review`，不静默改写历史。

## 三、使用操作

1. 在“论文库”完成 PDF 下载和全文索引。需要正式纳入科研结论的文字，先在原文证据区添加锚点、保存研究结论并人工确认。
2. 进入“研究助手”页面下的“科研综合与持续跟进” → “综合分析”，输入不少于 8 字的具体问题，例如“FNO 和 PINN 的跨网格泛化实验分别覆盖哪些条件”。
3. 可以不配置 API Key 直接运行。模型增强需打开折叠的设置，并明确勾选传输同意。
4. 检查每个结论链接的原文页码、方法对照和差异候选；通过“导出 Markdown”保存报告。
5. 历史报告可再次打开；如出现“依据变化，需复核”，按原文与人工修订重新确认。

## 四、主要限制

- 尚未实现全自动跨库多跳文献检索、医学/科学表格多模态语义归一，也未建立覆盖 100 篇真实 PDF 的人工评估。
- 方法比较是“方法名—论文—原文结论”矩阵；指标、任务、随机种子和训练预算不一致时，不会自动比较性能排名。
- 相反措辞仅给出复核线索；内容可能属于不同实验任务，不会自动判为科学冲突。
- 公开论文的题录和摘要不会自动升级为有原文支持的结论。模型可能出现无证据推断，其自由文本只用于待审解释。

## 五、测试与下一阶段验收

自动测试覆盖：完整 PDF 证据、报告 SHA 不可变、PDF 替换后的失效提示、未知结论 ID 拒绝、授权门槛、实验差异候选、主题隔离和公网会话隔离。正式质量验收需要人工标注的同一套科研问题，在新旧版本上对照证据命中、方法比较正确率、冲突候选精度和人工复核时间。当前未给出这些指标的实测数值。
