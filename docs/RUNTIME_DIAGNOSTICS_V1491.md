# v1.49.1 运行异常排查与日志下载

## 一、发生错误时如何操作

1. **先看错误提示。** 本地版若在生成关键词、测试模型或保存设置时失败，页面会给出错误原因。模型接口连接失败时，通常会显示“模型服务暂时无法连接”，并提供进入模型连接向导的入口。建议先检查服务商、密钥、模型名称、网络或接口地址。普通检索可直接使用手动填写的英文关键词，不要求模型可用。
2. **下载运行日志。** 点击页面右上角的 **下载运行日志**，或者在右下角任务状态栏点 **下载运行日志**。页面仍可打开时，也可在 **设置 → 运行记录** 查看“系统错误与请求”日志、点击刷新，再下载 ZIP。日志可在程序运行时随时下载。
3. **记下错误编号。** 对于服务器内部异常、数据库/存储异常和模型服务异常，页面显示 12 位错误编号。维护人员可在 ZIP 的 `runtime.jsonl` 中按 `request_id` 查找记录，查看接口、HTTP 状态、错误类别以及发生异常的文件和行号。
4. **页面无法打开时：**在程序根目录执行 `start_windows.bat --diagnostics`（Windows）或 `./start_macos_linux.sh --diagnostics`（macOS/Linux）。日志 ZIP 写入当前用户的 Downloads 文件夹；如果该文件夹不存在，则写入当前工作目录。此命令只打包已有日志，不启动文献任务，也不发起模型调用。
5. **需要更多上下文时：**在设置的运行记录区域勾选“同时附带任务日志”，或执行 `start_windows.bat --diagnostics --include-task-logs`。任务日志可能包含研究主题、关键词或失败信息，分享前请打开 ZIP 核对内容。

## 二、日志范围与安全边界

- 默认导出的 `runtime.jsonl` 仅包含时间戳、请求方法、接口路径（不包含查询字符串）、状态码、耗时、错误编号、错误类别和 Python 调用位置。诊断程序不会主动保存 API Key、密码、Cookie、研究问题正文、模型 Prompt 或 PDF 全文。
- 日志采用滚动保留机制：每个结构化日志文件约 2 MB，最多保留当前文件与两个历史文件。下载时不需要停止正在运行的科研任务。
- ZIP 默认包括 `runtime.jsonl`（如有）、轮转日志（如有）、`manifest.json` 和 `README.txt`。可选附带 `manual.log`、`scheduled.log` 和 `web_server.log`，对常见凭据模式执行尽力清理，但**无法承诺清除所有敏感研究内容**。与外部人员分享前请自行检查可选日志。
- 诊断 ZIP 不自动上传；由用户在本地下载后选择是否分享。日志下载要求本地工作台的安全令牌，不能通过普通 GET 链接跨站下载。
- 发生磁盘空间不足或日志目录权限问题时，日志写入失败不应阻止文献检索和正在运行的任务。此时可先检查硬盘与数据目录，再尝试导出既有日志。

## 三、日志与错误类型

| 提示 / 编号 | 可能原因 | 建议操作 |
|---|---|---|
| `MODEL_KEY_MISSING` | 当前服务商未保存有效密钥 | 打开“模型连接向导”，粘贴 API Key，保存后手动测试 |
| `MODEL_CONNECT_FAILED` | 接口不可达、网络、代理或地址问题 | 核查网络与服务商地址；先使用普通检索 |
| `MODEL_AUTH` | 密钥无效或服务商拒绝访问 | 检查密钥权限、服务商账户和模型使用范围 |
| `MODEL_BILLING` | 服务商额度或计费异常 | 检查模型服务商控制台 |
| `MODEL_RATE_LIMIT` | 服务商限流 | 减少请求，稍后重试 |
| `MODEL_CONFIG` / `MODEL_NAME_MISSING` | 模型名称或接口地址不匹配 | 在高级设置核对正确的模型 ID 和地址 |
| `CREDENTIAL_ACCESS` | 系统凭据管理器无法保存或读取密钥 | 检查凭据服务、Python 环境或重新安装依赖 |
| `INTERNAL_ERROR` | 服务端出现未预期异常 | 下载日志，连同错误编号提交维护人员 |
| 存储或数据库错误、HTTP 503 | 数据目录权限、数据库锁、磁盘或文件损坏等 | 检查存储状态，避免覆盖原数据库，下载日志排查 |

## 四、安装与升级注意

1. 更新前备份用户数据目录；不要把新的安装包解压到正在运行的程序文件上。
2. 若旧版服务还在后台运行，新启动器将检查版本号，不再悄悄连接到旧版本。请先在旧页面 **设置 → 运行记录 → 停止本地服务**。如有任务正在运行，应先等任务完成。
3. 关闭旧版后，在单独目录运行新版启动脚本。启动不会清空文献库；请保持原 `PAPER_RADAR_USER_HOME` 环境变量（如有）。
4. Windows 默认用户数据目录：`%LOCALAPPDATA%\Paper-Radar`，日志在其 `logs` 子目录；macOS 为 `~/Library/Application Support/Paper-Radar/logs`。以实际运行界面显示的用户数据路径为准。
5. 如果无模型密钥，普通文献检索仍可使用开放来源；生成 AI 检索词无法保证成功，页面会建议人工填写关键词。

## 五、本次故障的复现和验证范围

使用隔离用户目录、无真实付费密钥、不可访问的本地模型服务地址进行 HTTP 复现：v1.49.0 的 `/api/ai/plan` 返回通用 HTTP 500，前端只显示“服务处理失败”，没有可匹配的异常记录；v1.49.1 返回可解释的模型连接错误、错误编号，并记录不含密钥和研究问题正文的结构化日志。PDF、文献数据和网页操作分别通过隔离测试验证。

目前没有原故障设备的真实运行日志，因此本次修复不能证明截图里出现的所有故障都来自模型连接。若新版仍有故障，请提供默认诊断 ZIP 和页面显示的错误编号，便于继续定位。
