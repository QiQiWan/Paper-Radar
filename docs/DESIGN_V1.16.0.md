# Paper-Radar v1.16.0 · 设计审查、已实现内容与研发路线

## 一、总体判断

当前桌面系统原本默认信任本机工作台，包含 Zotero、本地 PDF、凭据和系统操作等高权限能力。增加账号登录后直接绑定公网会造成过高的攻击面。本轮采取**共用基础代码、独立公网服务入口、独立账号数据库和有限开放功能**的结构，同时在桌面版增加 SynthesisAgent、数据库版本迁移和独立发布签名链。公网用户之间默认不共享文献、账户信息和实验证据。

当前已实现**受控公网功能集**，尚未实现桌面版全部能力上线、正式多租户 LLM API Key 隔离、全文 PDF 云处理或邮件验证。生产开放大量自助注册前须增加公网服务强化措施。

## 二、架构与边界

```text
                                Paper-Radar 源代码库
                          ┌──────────────┴──────────────┐
                    桌面版（仅 127.0.0.1）       公网门户（仅 127.0.0.1）
                  本地 API / Zotero / AI         用户登录、CSRF、账号隔离
                   ┌──────────┴─────┐           ┌───────────┴──────────┐
                  9个主Agent    4个实验Agent     arXiv检索 / CSV导入 / 比较
                   └───────┬────────┘           账户库 + 独立用户工作区
                       3个SynthesisAgent               │
                 共享本地文献 SQLite                Nginx HTTPS 反向代理
```

桌面版保留本地 API 和完整文件管理；公网服务只导出 `/api/public/` 受控路由。公网按随机账号 ID 派生独立 SQLite 目录，用户无法提交服务器真实文件路径。账密使用 scrypt + 随机盐、会话服务端 SHA-256 存储、HttpOnly/SameSite Cookie、CSRF 和 Origin/Host 检查、限流和账号禁用。公网绑定 127.0.0.1，由 HTTPS 反向代理实现外部访问，端口由脚本参数指定，并可通过 `tools/render_public_nginx.py` 为指定域名和端口生成对应反向代理配置。

## 三、独立发布签名与回滚

**离线密钥与固定信任**：发布者保管 Ed25519 私钥，客户端源码内嵌公钥；发布时对包含版本/仓库/ZIP 摘要/大小/协议的清单进行签名。新版自动安装同时验证官方 GitHub Release 元信息、受信任签名、ZIP SHA-256、路径安全及程序协议。签名私钥不可出现在 GitHub、账号系统与发行包中。

签名密钥轮换必须由旧版可信客户端能验证的过渡版本进行。第一次从没有固定信任根的 1.15 升级到 1.16，需要受控的人工操作。在服务正在运行或备份失败时禁止热更新；数据库回滚可能造成升级后新数据丢失，生产系统应采用维护窗口和独立备份。

## 四、数据库生命周期

`schema_migrations` 将研究、账号、用户工作区迁移分开记录，并使用内容校验摘要确保迁移历史未被静默修改。新版本拒绝打开高于代码能处理的数据库版本；继续沿用旧版论文数据结构，增量增加综合分析历史表。写数据库前先备份并试运行，公网账号数据与本地研究库不会自动合并。参见 [数据库迁移说明](MIGRATIONS_V1.16.0.md)。

## 五、SynthesisAgent 设计

三阶段：`EvidenceCollectAgent` 获取当前主题、当前 PDF 指纹有效的结构化实验证据；`SynthesisAgent` 将论文按数据集、指标、实验设置等条件分组，并把可疑不可比性单独列示；`SynthesisExportAgent` 输出 Markdown 并登记历史。默认不调用额外云端模型，避免无依据数据合成；原始数据有 `paper_id`、DOI、页码、引文、指标、数值、基线和设置条件。

严格区分：论文数据聚合、**同条件候选比较**与正式学术结论。即使数据集名称和指标一致，训练/测试划分、模型容量、随机种子与硬件可能仍不同，系统不会自动对跨论文数值计算优劣排名。公网 CSV 导入结果标记为 `user_import`，无法代表原始 PDF 在服务器侧已复核。

## 七、下一阶段优先级

P0（公网真正面向公众前）：加邮箱验证/密码重置、全局请求速率限制、反机器人、可靠后台任务队列、定时 SQLite 备份、TLS/服务器安全基线和跨用户隔离的动态安全测试。建议 PostgreSQL + 工作队列适配并审查高并发和数据库锁争用。

P1（科研深度）：为 SynthesisAgent 补充分任务的数据标准化（单位/指标方向/数据划分）、基于真实论文的人工标注比较集，建立错误比较率与证据准确率 KPI；改善复杂表格的结构提取和跨页识别。

P2（产品体验）：接入可选的邮件日报、账号配额可视化、云端多来源检索与模型服务商按用户的独立密钥管理，并实现桌面与公网用户数据的显式授权同步；持续迭代移动端 UX。
